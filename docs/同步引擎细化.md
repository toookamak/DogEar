# DogEar · 同步引擎细化（v0.2）

> 实施级细化，关联 PRD v0.3.8、技术方案路线 v0.3、部署方案 v1.0 与 600 条基线。

## 0. 原则
- 本地优先：写即时落当前端缓存或服务端，sync_queue 异步推 Raindrop，不阻塞操作
- 服务端为真源：Workers 使用 D1，Docker 使用 SQLite；IndexedDB 仅作端侧缓存
- 增量优先：先做 collection 级变化探测，只有发生变化时才拉取详情，避免例行全量获取
- 速率监测：条数/秒、时延、成功率、队列长度、限频次数（对接 PRD 05.2）

## 1. 队列
- **结构**：`{id, bookmarkId, op:create/update/delete, payload, attempts, nextRetryAt, status:pending/success/failed/conflict}`
- **顺序**：按 updatedAt 顺序消费，单条失败指数退避（1s→2s→4s…封顶 5min），不堵后续
- **持久化**：存本地，队列保留至成功或冲突解决

## 2. 频率（已确认默认值，可配）
- **推送**：约 30s 轮询 sync_queue，按限速逐条推
- **拉取**：5min / 15min / 手动 三档（设置可改），对比 lastSyncAt 拉增量，支持“立即同步”按钮

## 3. 限频与重试
- **信号**：Raindrop 429 读 Retry-After，暂停队列，指数退避
- **体感**：本地编辑仍即时，顶部同步状态 + 轻 Toast 提示“限频等待 N 秒”，日志可见，不丢数据
- **断网**：队列保留，联网后自动续推
- **Toast 说明**：角落 3 秒自动消失的轻提示，不需点击确认，仅用于告知限频等待；冲突不使用 Toast

## 4. 冲突（已确认细化）
- **触发**：同 id/url 在本地与远端均有更新且 updatedAt 交叉
- **保留**：用户未做选择时，两端数据皆保留，队列标记 conflict，不自动覆盖
- **提醒**：工作台常驻入口“发现 N 条冲突，去处理 →”，非 Toast
- **视图**：列表展示冲突条目，左右对比（本地 | 远端：标题/文件夹/标签/备注/时间）
- **操作**：单选或全选，支持“用本地覆盖 / 用远端覆盖 / 手动合并 / 稍后处理”；支持批量“全部用本地/全部用远端”
- **默认**：未进视图前不自动推冲突条目，避免误覆盖

## 5. 速率监测
- 指标：推送/拉取 条数/秒、平均时延、成功率、队列堆积、429 次数
- 展示：设置 > 同步 与日志中可看，用于 600 条考核

## 6. 历史与恢复边界
- 书签删除先进入软删除状态，默认保留 7 天；窗口内可从回收站恢复，过期后由清理任务物理删除
- Workers 轨使用 D1 Time Travel 作为服务端灾难恢复兜底，保留周期遵循 Cloudflare 计划（Free 7 天，Paid 30 天）
- Docker 轨每日生成 SQLite 滚动快照，默认保留 7 份，可在设置中降低或提高
- 不做 UI 级任意操作撤销与无限快照链；日常迁移/备份使用 Web 界面导出的 JSON bundle，包含 schema 版本并在导入前校验
- 历史清理按 `retentionCount=5000` 与 `retentionDays=30` 双阈值执行，避免 operation_log 无限增长

## 7. 资源预算与监测
- 600 条基线下，默认 5 分钟探测最多 288 次/天；若无变化，每轮仅消耗一次 collection 探测请求
- 推送使用 30s 合并窗口和批量接口，避免同一条书签的重复 update
- 429、失败重试、队列长度和全量任务均纳入同步监测；记录推送/拉取条数、耗时、成功率、重试次数与最后错误
- Worker 静态资源使用 Cache API；favicon 等外部资源由浏览器按需加载，不经服务端转发

> 默认配置可调，改配置后由下一轮同步任务生效。
