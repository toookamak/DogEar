## 1. 原则与约束

### 产品约束（PRD，此处不改）

- 应用数据为真源；不接任何第三方，产品完整可用
- **能连上本应用即可保存**；第三方未配置或中断不阻塞保存；应用不可达时本版不承诺仍能存
- Raindrop / S3 / WebDAV 等是数据管理选项，不是登录门槛
- Raindrop 只作**输入源**和/或**导出存档**，不是默认双向持续同步；不做双端 CRDT
- Scene、AERR、导航圈选、AI 建议、Inbox 语义不进入第三方存档
- 保存与内容保全解耦：Capture 只建 Link；Snapshot 是保存之后的事
- 不为愿景（Reader、移动端 Share 等）做当期方案
- 600 条是性能基线，不是产品上限；非核心功能不得拖累保存 / 搜索 / 工作台主视图 / 导航页首屏

### 本章要定的

- 把上面几条写成工程规则时，边界怎么检查（例如：「应用可达」指什么）
- 哪些约束是实现红线，哪些只是默认策略、允许配置

### 不在本章写

实现栈、队列字段、页面流程。

## 3. 逻辑架构：有哪些端、应用是什么

先定「系统由几块组成」，再谈数据存在哪、功能怎么转。

### 产品约束

本版优先三个入口 + 一个展示面，都连**同一份应用数据**：

| 端 | 职责（产品） | 本版要不要有 |
| --- | --- | --- |
| 工作台 | 整理、搜索、设置、圈选导航范围、备份入口 | 要 |
| 浏览器插件 | 当前页保存 Link；保存后可触发 Snapshot | 要 |
| Skill API | Agent 保存 Link、搜索、触发单条 Archive | 要 |
| 导航页 | 日常打开入口；展示工作台圈定的范围 | 要（基础形态即可） |

移动端 / Share / 其他 App：非本版优先。

### 本章要定的

1. **「应用」是什么**  
   插件、Skill、工作台、导航页都要「连上应用」才能保存。这个应用是：
   - 仅浏览器内的一份数据？
   - 本机上的一个服务？
   - 用户可选择部署到某处的服务？
   - 还是「端 + 可选服务」分层？  
   PRD §8.1 只说本地 / 服务器 / 其他，**未定**。§8.x 的 Workers + D1 是历史候选，不作为本章结论。

2. **四个端如何共用同一份数据**  
   同机、同浏览器、跨设备，分别怎么连。多设备策略见 PRD §8.2：无公网则单机；有服务端则以服务端为真源；兜底靠备份。

3. **端与端的关系**  
   导航页是独立壳还是工作台的一种视图；插件是否必须经应用服务，还是可以直接写存储。

逻辑关系（示意，不是部署图）：

```
页面保存 / 插件 / Skill / 导航页
              │
              ▼
           应用核心
         （读写、任务、鉴权）
         /            \
  结构化数据              内容数据
         \
          可选通道（Raindrop / S3 / WebDAV）
```

### 不在本章写

具体框架、进程模型、端口、同域策略。那些跟 §7 一起定。

## 4. 数据：有哪些对象、存在哪一层

盘对象，不盘字段。字段以 PRD 附录 C 为准。

### 4.1 对象清单（产品已出现、技术上必须有落点）

| 对象 | 解决什么 | 出不出应用 |
| --- | --- | --- |
| Bookmark（Link 级） | 长期网页引用 | 同构字段可进可选导出 |
| Folder / Tag | 用户自己的位置与主题 | 可随导出写出 |
| Status（待处理 / 已确认 / 搁置） | 处理程度 | 仅应用内 |
| Scene + 成员关系 | 为什么保存 / 在什么情境用 | 仅应用内 |
| 收藏标星 | 我更在意 | 可随导出写出 |
| 导航圈选规则、页面标签、Docker 项 | 导航页展示什么、怎么摆 | 仅应用内；关导航页不丢 |
| 访问记录 | 打开过、打开几次 | 仅应用内 |
| AI 建议 | 尚未写入结构的建议 | 仅应用内 |
| Archive Job / Archive Record | 内容保全任务与结果指针 | 仅应用内 |
| Snapshot 内容 | 网页保全副本 | 内容层；不进 Raindrop |
| 操作日志 / 回收站 | 可追溯、可恢复 | 仅应用内；导出默认不含回收站 |
| 数据管理配置与凭证 | 通道开没开、怎么连 | 仅应用内（加密存放方式待定） |
| 任务队列 | 导入 / 导出 / 备份 / Archive 的未完成工作 | 仅应用内 |

Reader、用户自定义扩展属性：愿景或仅声明，当期不设计存储方案。

### 4.2 分层（产品方向已定，落点未定）

PRD：结构化数据与内容数据分开放、互不依赖。

| 层 | 装什么 | 落点 |
| --- | --- | --- |
| 结构化 | 上表除 Snapshot 内容以外 | 应用数据库；端侧 / 服务端 / 引擎均未定 |
| 内容 | Snapshot 等大对象 | 内容存储层；形态未定（对象存储只是方向） |

「端侧缓存 + 服务端真源」是 PRD §8.x 的历史候选，不是本章结论。先定 §3 的「应用是什么」，再定这里有几层副本。

### 本章要定的

- 应用内主键是什么；Raindrop `_id` 只是导出映射还是某种外部键
- 结构化与内容的接口：Record 如何指向内容对象
- 配置、日志、队列是否与 Bookmark 同一套库
- 私密标记落在 Folder/Tag 还是 Bookmark 上（产品有方向，存储形态未写）

### 不在本章写

表结构、索引、ORM、附录 C 的逐字段复述。

## 5. 按功能看数据流

每一节对应 §2 的能力编号。只问：**读什么、写什么、经过哪一层、是否碰第三方、失败时数据停在哪。**  
不写页面、文案、按钮。

统一模板（讨论时按此填）：

```
读：
写：
经过：结构化 / 内容 / 可选通道
失败：
```

### 5.1 保存（页面 / 插件 / Skill）

对应能力：C1 / C2 / C3 / C4。

**产品约束**

- 三端默认结果都是 Link；不在保存时选档
- 默认进 Inbox（待处理）；不强制选 Scene / Folder / Tag
- Skill 可选 `note` / `intent`；不在 save 上写结构
- 异步补 Metadata / 理解，不阻塞保存
- 本版不定义 URL 去重规则

**要填的数据流**

- 最小写入集（至少 URL）落到哪
- Metadata 抓取是写 Bookmark，还是单独 Job
- `intent` 是建议的输入，还是持久字段
- 插件用当前 DOM 时，DOM 是否离开浏览器

**待讨论**：三端是否走同一条「创建 Bookmark」接口。

### 5.2 整理（Inbox / Scene / Folder / Tag / Status）

对应能力：O1–O5、O7、S2。

**产品约束**

- 四个维度独立、可组合；Inbox 不强制清零
- Scene 多对多；第一版不做 Primary Scene
- 整理模式与导入梳理页是可选加速，不是义务
- 改结构只发生在应用内

**要填的数据流**

- 改 Scene 成员 / Folder / Tag / Status 各写哪些对象
- 批量改与单条改是否同一写入路径
- 是否产生操作日志（PRD 要求写操作可追溯）

**待讨论**：查询（按 Scene 且按 Tag）是应用内组合查询，还是预计算。方向倾向前者，未定。

### 5.3 输入（把已有库引进来）

对应能力：D2、O5。

**产品约束**

- 仅当用户把某通道选成输入源时才发生
- 读入对方同构字段；Folder / Tag 保持原样，不把对方数据变成 Scene
- 首次：用户选「进 Inbox」或「保持原路径」，可走梳理页
- 首次梳理之后：该源新来的零散记录进 Inbox

**要填的数据流**

- 首次全量 vs 之后增量，如何发现「新来的」
- 对方 ID 与应用主键如何对照
- 梳理页改的是即将写入的应用数据，还是先落再改

细部（嵌套 collection、向导文案等）仍在 [暂存稿](DogEar_折耳书签_技术方案_v0.1_draft.md)，讨论完本节再决定去留。

### 5.4 导出存档（把 Link 级记录送出去）

对应能力：D3。

**产品约束**

- 目的是存档，不是镜像 DogEar 工作方式
- 写出 Link 级同构字段；不写 Scene / AERR / 圈选 / AI 建议 / Inbox 语义 / 删除标签
- 回收站默认不进存档
- 无产品入口的对方字段（高亮、提醒、附件等）：随通道保留、不做成功能

**要填的数据流**

- 触发：手动、定时、还是「有变更再送」——产品没有 30 秒推 / 5 分钟拉
- 成功后是否回填对方 ID，便于下次增量
- 失败重试停在哪条队列

**待讨论**：导出与 §5.9 三档备份是否共用任务模型，还是两套。

### 5.5 导航页

对应能力：R3。

**产品约束**

- 工作台写「是否显示」，导航页管布局
- 圈选：全部 / 按规则（或） / 自定义搜索勾选 / 隐藏
- 关闭导航页不丢 `page_tab` / Docker
- 私密默认不出现，除非规则明确纳入且需解锁
- 第一版默认随工作台登录

**要填的数据流**

- 圈选规则的存储形态（规则表达式 vs 物化 ID 列表 vs 每次打开重算）
- 导航页读结构化数据的哪一个快照：直连应用，还是端内缓存
- 布局数据与书签数据是否分开存

### 5.6 搜索与访问记录

对应能力：R1 / R2、O7。

**产品约束**

- 核心：搜标题 / URL / 标签 / 备注，可按 Scene 等过滤
- 打开原链接（及日后打开 Snapshot）要记访问
- 访问记录不进 Raindrop
- 「N 年前今天」等 Rediscover 卡片为近期，核心先落库

**要填的数据流**

- 搜索范围是否含 Snapshot 正文（倾向：核心不含，避免拖核心路径）
- 访问记录最小字段；是否区分工作台 / 导航 / 插件
- 记在 Bookmark 上还是独立流水

### 5.7 Archive / Snapshot

对应能力：A1–A3、C4。

**产品约束**

- 与 Bookmark 解耦；Job 失败不回滚 Link
- 当前类型：Metadata 抓取、Snapshot；Reader 不做
- 来源：server / browser / agent / manual
- 内容不进 Raindrop

**要填的数据流**

- Job 记在结构化层，内容进内容层；指针怎么写
- 浏览器生成 vs 服务端拉取（PRD §8.x 倾向浏览器直传，**未定**）
- 内容存储中断时 Job 可失败重试，Bookmark 保持已保存

### 5.8 AI 建议

对应能力：O6 / O7。

**产品约束**

- 保存后异步理解；建议 1 个 Scene 和很少的 Tag/Folder
- 出现在：输入时、整理时、Inbox、未整理详情
- 默认不自动写入结构；可撤销
- 禁止：删除、改文件夹结构、未经确认的自动分流
- 组织记忆、闲置迁移：近期，不作为当期能力承诺

**要填的数据流**

- 建议是独立对象，还是未采纳就不落库
- 采纳时写入 Scene 成员（及可选 Folder/Tag），并记操作日志
- 理解流水线读哪些字段（URL / 标题 / 正文 / intent）；正文从哪来
- 私密标记如何排除出记忆（近期）

能力自描述、Token：见 §8 与 Skill 模块。

### 5.9 备份与恢复

对应能力：D5、A3、D4。

**产品约束**

- 轻：Link 级 HTML/CSV/MD（HTML 为 Netscape 收藏夹格式）
- 中：+ 配置
- 重：完整库 + Snapshot + 配置
- 目标可走 S3 / WebDAV 等，与通道选项一致、可独立启用
- 另有单条 Snapshot 导出（先选内容再选格式），与三档备份互不替代

**要填的数据流**

- 轻档是否等于「对任意目标的 Link 导出」，还是独立打包
- 中档「配置」含哪些对象（Scene、圈选、主题、通道配置）
- 重档是存储层快照，还是应用导出包
- 恢复时与现有库：覆盖、合并、还是新库

### 5.10 设置与首次数据管理

对应能力：D1、S4。

**产品约束**

- 首次不引导登录 Raindrop；只引导数据管理选择，可跳过、可多选、可稍后改
- 通道凭证事后在设置中改

**要填的数据流**

- 向导写入哪些配置对象
- 跳过 = 零通道，应用仍可保存

向导步骤与文案进模块，不在总纲展开。

## 6. 可选通道

通道是挂在应用之外的管子，不是真源。§5.3 / §5.4 / §5.9 是通道上的功能；本章定通道本身。

### 产品约束

- 选项：Raindrop、S3、WebDAV 等，可跳过、可多选
- Raindrop：输入和/或导出，角色可只开一个
- S3 / WebDAV：PRD 不规定接到备份包还是内容对象
- 遇对方限频则退避；不做复杂离线包

### 本章要定的

- 多通道并存时：输入、导出、备份、内容存放是否允许同时开，彼此是否互为备份
- S3：备份目标、内容存储、还是二者（接口可同一，用途要分开说）
- WebDAV：是否主要当备份盘
- 凭证存放与权限范围（Raindrop token / S3 密钥 / WebDAV 账号）
- 任务模型：是否一条通用队列覆盖导入、导出、备份、Archive

### 不在本章写

Raindrop 字段对照（附录 C）、向导文案、设置页布局。

## 7. 部署与运行

§3 定「应用是什么」的逻辑答案；本章定跑在哪。**未讨论前不定选型。**

### 产品约束

- 部署方向可选：本地 / 服务器 / 其他
- 多设备：无公网则单机；有服务端则以服务端为真源；换机可靠备份恢复
- 工作台必须鉴权；Skill 用 Bearer Token
- 核心路径要能在 600 条基线下保持流畅

### 本章要定的

- 工作台、导航页、插件、Skill 各跑在哪一类环境
- 有无「必须存在的服务端进程」
- 结构化存储、内容存储各用哪类载体（只定类别：嵌入式库 / 服务端库 / 对象存储 / 浏览器存储……）
- 两套部署是否要同一份业务代码（PRD §8.x 曾假设双轨同构，**未定**）

### 明确不是本章结论的

PRD §8.x 与 `docs/Draft/` 里的 Workers + D1 + R2、Docker + SQLite、IndexedDB 缓存、30 秒推 Raindrop。那些是旧讨论，与「Raindrop 改为可选存档」不完全兼容。需要时对照 [附录](#12-附录历史候选不定稿)。

## 8. 鉴权、隐私、性能

横切，约束落到所有 5.x。

### 8.1 鉴权与隐私

**产品约束**

- 工作台必须鉴权
- 公网：密码页 / URL Token / IP 白名单等（方向，未定形态）
- 本地：内网 + 安全隧道等（方向）
- Skill：Bearer Token
- 私密 Folder/Tag 默认不进导航；查看需解锁
- 导航匿名访问不是默认能力

**待讨论**：插件、导航页、Skill 是否共用同一套身份；凭证与通道 token 是否分开存。

### 8.2 性能与观测

**产品约束**

- 核心路径：导航首屏、工作台主视图、保存、检索
- Archive、小组件、统计不得拖核心
- 导入 / 导出 / 与外部交换：条数/秒、时延、成功率、队列、限频要能看见

**待讨论**：观测落在应用内什么地方（设置页 / 日志）；是否要独立指标对象。

### 8.3 日志与回收站

**产品约束**

- 写操作进日志；有容量与时限（曾提 5000 条 / 30 天可改，落地时再定）
- 软删除进回收站；清空是否影响已导出存档 → 产品倾向不影响，实现要守
