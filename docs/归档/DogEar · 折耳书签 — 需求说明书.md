# 01. 产品定义

## 01. 产品定义

### 1.1 定位

Bookmark Enhancer 是一个基于 Raindrop.io 的个人书签增强工具。以 Raindrop 为数据底层，通过 **Skill API + 工作台 + 个人导航页** 三部分，构建一套个人书签的收藏、整理、浏览闭环。

### 1.2 核心理念

- Raindrop 是数据存储和稳定性的保障，不替代它，而是在其之上构建更灵活的交互层
- **本地优先**：数据默认存在本地，操作即时响应，定时异步推送到 Raindrop（Raindrop 作为备份与跨端通道，具体同步策略见 04.3）
- AI 能力以 Skill 形式暴露，不绑定任何特定 AI 平台
- 纯个人工具，不考虑多人协作，安全和隐私优先
- **功能要丰富，流程要清晰，使用要简单**；情景驱动是设计方法，不是硬性约束
- **性能优先**：不为非核心功能增加过多性能负担，必要时可精简功能（需与用户确认）；最终以页面响应与数据读写为考核项

### 1.3 目标用户

个人用户（本项目为自用设计），有大量书签收藏和整理需求，日常工作涉及多平台信息收集。

# 02. 用户需求与核心工作流

> 以下为用户在讨论中明确提出的思路和要求，按提出顺序整理。

### 2.1 基础需求

1. 做一个书签工具，数据基于 Raindrop，通过 API 互通
2. 基于 Raindrop 做一个更加便捷的收藏和编辑界面
3. 具有 AI 录入、稍后读清单
4. 快捷编辑分类和其他便捷功能
5. 个人使用，不是团队场景
6. 独立的 Web 界面；移动端后续考虑，初期以桌面端为主（见 04.10）

### 2.2 痛点描述

1. 现有 Raindrop 收藏形式单一，大多数情况通过浏览器插件收藏
2. 浏览器插件的收藏界面编辑条件有限，只能写文字和标签
3. 收藏后只有文件夹和标签可以归类，管理维度单一
4. Raindrop 主页只有基础的文件夹和书签分类功能，管理界面不够灵活
5. 看中 Raindrop 的数据稳定性且多平台可取，希望以 Raindrop 做数据核心

### 2.3 AI Agent 相关

1. AI 主要是 AI Agent，可以随时随地使用，只要有一个链接发给 Agent 就能完成收藏
2. Agent 自己填写基础必要的内容：根据页面内容属性放在合适的文件夹，打上稍后读标签
3. 用户只需要提供一个链接即可，有什么需要记录的也可以告诉 Agent
4. Skill 不应绑定特定 AI 平台，提供 base URL 和 token 即可，AI 通过链接自描述获取能力
5. 绑定时只需要给 AI 一个链接和 token，AI 自己去发现能做什么，不需要用户反复说明
6. 不排斥 Raindrop 只是数据保存的一种途径，只要数据能安全稳定保存，本地可以做丰富一点
7. AI 对用户的收藏与访问内容有一定学习与记忆，支持模糊关联检索（见 04.1.3）

### 2.4 工作台相关

1. 电脑前闲暇之余，在工作台上快速点开稍后读列表，查看哪些内容未整理
2. 需要收纳的收纳，需要阅读的阅读
3. 希望包含拖拽等多种形式，依托 Raindrop 基础功能（如标签）做管理和分类
4. 支持多种形式组织内容：看板、表格、网格等，快速浏览和整理收藏
5. 整理模式可以做，暂时还没想好具体形态，可以按情景分，也可以按功能拆分
6. 批量整理为 AI 自动回填信息 + 用户确认的模式（见 04.2.5）

### 2.5 数据同步

1. 数据默认存在本地，定时异步推送到 Raindrop 进行保存（本地是真源，Raindrop 是备份与同步通道）
2. 定期获取 Raindrop 的数据，以便对通过插件收藏的内容进行同类型整理
3. 双向同步需考虑网络波动与官方 API 限频，本地操作不因同步阻塞
4. 可以考虑部署应用，也可以考虑做成浏览器插件形式，按需求定方向，具体技术路线待定
5. 期望操作灵活、数据安全、兼容性好
6. 接受本地优先 + 异步同步的策略
7. Phase 1 需要包含 Raindrop 的数据获取和写入，整个流程要打通，功能后续根据体验慢慢扩展
8. 多设备策略见 07 章：本地部署为单机，服务器部署可多端，Raindrop 定时备份为兜底

### 2.6 导出与备份

1. 需要快速导出与备份功能，方向上分为三档（见 04.7）：
    - 轻：通用格式，浏览器/第三方可读（HTML/CSV/Markdown）
    - 中：带个性化配置的配置文件，导入可还原核心内容
    - 重：快照级原封不动备份
2. 备份用于迁移、重装还原与灾备

### 2.7 安全与约束

1. 既要限制 AI 非常规情况的能力，也要有兜底机制可还原
2. 要限制 AI 的操作范围，比如不能快速破坏数据（一键改动、一键删除、饱和式填充等极端情况）
3. 个人体验为主，不需要考虑多人分享
4. 要考虑安全性：公网部署需要鉴权，本地部署也需要考虑隐私页面的收藏
5. 软删除机制，保留可恢复周期；操作日志有容量与时限约束，支持清理与导出（见 05.1.2）

### 2.8 导航页

1. 可以延伸做个人主页导航，以浏览器插件或其他形式，依据内容做成个人导航页
2. 导航页看资源情况设计，可以放在后续阶段
3. 设想：工作台可标记“是否在导航页展示”，导航页侧决定展示样式与位置，强/弱关联待定（方向性设想）

### 2.9 其他设想（方向性）

1. 后续可能延伸 Markdown 轻量剪藏（仅图文，无重附件）
2. 看板等多视图支持多维度切换（状态/文件夹/标签/优先级/时间/情景）
3. 导航页小组件优先开放核心类型：待办/稍后读/便签/书架/资讯

# 04. 核心功能设计

> 本章为功能与交互方向，具体技术实现待定。

## 4.1 Skill API

### 4.1.1 自描述机制

AI 平台绑定时只需提供：

- 服务地址（Base URL）
- 访问令牌（Token）

AI 通过访问 `/.well-known/capabilities` 端点自动获取可用能力列表、参数说明和使用示例。

### 4.1.2 Skill 清单

| Skill | 描述 | 输入 | 说明 |
|---|---|---|---|
| `save_bookmark` | 收藏一个链接 | url（必填）、note（可选） | 自动抓取元数据、AI 分类、生成标签、标记稍后读 |
| `search_bookmarks` | 搜索书签 | query、filters（可选） | 支持自然语言和条件筛选（见 04.8） |
| `update_bookmark` | 修改单条书签 | id、修改字段 | 文件夹/标签/备注/状态 |
| `list_bookmarks` | 列出书签 | 状态、文件夹、标签、limit | 支持筛选和分页 |
| `get_stats` | 获取统计信息 | 无 | 收藏总数、各分类数量等 |
| `batch_organize`* | 批量整理（方向性） | ids 或 filters | AI 回填信息，需用户确认后生效（见 04.2.5） |

*`batch_organize` 为 Phase 2 方向，具体入参以实现时为准。

### 4.1.3 AI 记忆（偏好学习与关联检索）

**目标**：AI 对用户的收藏与使用有一定的学习与记忆，能在用户模糊提问时关联找回历史内容（例如“上次那个 xx 技术贴”）。

- **记忆来源**：分类与标签选择偏好、阅读习惯、文件夹组织逻辑、常用搜索模式、整理时的决策倾向等
- **触发**：每次 AI 执行保存/整理后记录模式，累积形成偏好；搜索时自动参考记忆提升相关度
- **能力**：支持自然语言关联检索（标题/标签/摘要/来源的综合召回），无需用户提供精确关键词
- **管理**：用户可在 `设置 > AI` 独立页预览记忆内容，支持修改与重置；但入口收敛，不鼓励频繁手动编辑，默认以 AI 自动沉淀为主；日常仅需绑定 Base URL + Token + Skill 即可具备基础使用，无需进入 AI 设置
- **约束**：记忆数据存服务端，随 Skill 调用自动参考；隐私内容可标记不进入记忆；具体存储结构与算法待定

## 4.2 工作台

### 4.2.1 整体布局

- 左侧：导航栏（待处理、收藏、最近、文件夹树、标签云、统计、导出、日志）
- 顶部：快速搜索（⌘K）、同步状态、设置入口、工具面板开关
- 中部：主内容区，支持视图切换
- 右侧：可折叠工具面板（见 04.2.7，默认收起，宽约 300px 方向）
- 底部：状态栏 / 批量操作栏

### 4.2.2 视图模式

| 视图 | 描述 | 适用场景 |
|---|---|---|
| 网格视图 | 卡片式，展示封面图 + 标题 + 标签 | 快速浏览、凭直觉分类 |
| 列表视图 | 紧凑行，一屏展示更多条目 | 批量扫描、批量操作 |
| 看板视图 | 按状态分列（未读/在读/已整理） | 追踪阅读进度、管理稍后读 |

> 看板后续可支持多维度切换（按文件夹/标签/优先级/时间/情景分列），为方向性设想，具体维度待定。

### 4.2.3 整理模式（Inbox Zero · 两阶段分拣）

> 方向已确认：两阶段流程，兼顾少量与大量场景。

**布局**：左右分区，左侧紧凑列表 + 右侧预览面板（或侧滑预览，方向性）

**阶段一 · 分拣（是否保留）**：
- 目标：快速判断每条是保留 / 删除 / 待定
- 待定：用于需打开原网页浏览后才能判断的条目
- 少量（<10 条）：逐条点击保留/删除/待定
- 大量（>10 条）：支持多选 + 批量标记，或“全部保留/全部删除/全部待定”快捷操作
- 每条操作后实时显示统计：✓保留 N / ✕删除 N / ?待定 N / 未处理 N
- 支持撤销；界面紧凑，一次展示全量待处理

**阶段二 · 细分拣（如何分类收纳）**：
- 仅展示阶段一标记为“保留”的条目
- 每条展示 AI 建议的文件夹 + 标签
- 用户可逐条采纳/修改，或批量采纳 AI 建议
- 可跳过阶段二，直接用 AI 默认建议归档
- 若待处理仅 1-2 条，可跳过阶段一直接进阶段二

**右侧预览面板**：
- 内容：标题、URL（附“在浏览器中打开”）、AI 摘要、AI 建议分类/标签
- 交互：点击列表条目切换预览；点击“在浏览器中打开”新标签页跳转，阅读后切回继续处理
- 约束：页面内不直接嵌入外部网页（跨域限制），以摘要与链接为主

**工作台联动**：工作台右侧“待处理”tab 底部提供“进入整理模式”入口，两处数据与状态联动（方向性，具体联动细节待定）。

### 4.2.4 内联编辑

悬浮卡片时浮现操作区：

- 点击文件夹 → 下拉选择器，可移动
- 点击标签 → 标签选择器，可增删
- 点击状态 → 循环切换
- 快捷操作：移动、打标签、标记已读、更多菜单

### 4.2.5 批量操作

多选后出现批量工具栏：

- 移动到文件夹
- 添加标签
- **AI 批量整理**：AI 自动获取书签相关信息并回填（标题/摘要/文件夹/标签等），结果以预览列表呈现，需用户逐条或一键确认后才生效，支持回滚/撤销
- 标记已读
- 删除（需确认）

> 方向：AI 回填为建议态，不直接写库；确认流程与回滚机制待细化。

### 4.2.6 快捷键（方向性）

| 范围 | 按键 | 功能 |
|---|---|---|
| 全局 | ⌘K | 快速搜索/命令面板 |
| 全局 | N | 快速收藏（弹出输入框） |
| 整理模式 | Enter | 采纳 AI 建议 |

| 通用 | Space | 列表中预览 |

### 4.2.7 右侧工具面板（可折叠）

| Tab | 内容（方向性） |

## 4.3 本地数据层（方向性）

> 仅描述功能诉求，不定技术方案。具体存储引擎、表结构、同步实现待定。

### 4.3.1 数据与日志

- **使用存储**：日常读写的数据，需即时响应、结构清晰
- **备份存储**：用于备份/恢复的数据，可舍弃非必要信息（操作日志、同步状态、临时缓存等），与使用存储不必完全一致
- **操作日志**：记录所有写操作，支持查看与回滚；**有容量与时限约束**（默认设一个初始值，例如 5000 条/30 天方向性，用户可在设置中自行修改），支持用户导出清理、直接清理、自动定期清理、循环覆盖；默认采用循环存储，旧日志滚动覆盖
- **软删除**：标记删除后保留一定周期，可一键恢复

### 4.3.2 同步引擎（方向性）

**写入（本地 → Raindrop）**：
用户/AI 操作 → 写入本地（即时）→ 进入待同步队列 → 后台按限频逐条推送

**读取（Raindrop → 本地）**：
定时拉取或手动刷新 → 对比增量 → 处理冲突 → 写入本地

**频率（已定）**：推送采用 30 秒合并窗口；拉取默认每 5 分钟，支持 15 分钟或手动触发，后台可配置。

**冲突处理（已定）**：
- 双端数据均保留，不自动覆盖
- 提供冲突视图，用户可选择“用本地的/用 Raindrop 的/手动合并”

**离线（方向性）**：不做复杂离线投入。无网时本地浏览与编辑可用，同步操作排队，联网后重试；不单独设计重型离线队列 UI。

## 4.4 组织维度（方向性）

> 新增维度通过标签约定兼容 Raindrop，但不限制未来本地可扩展更丰富字段。

**情景维度**：
- 用途：学习材料 / 工作参考 / 灵感收集 / 娱乐消遣
- 项目关联：关联到具体项目
- 优先级：高 / 中 / 低

**时间维度**：
- 定期回顾：每周/每月回顾
- 时效性：永久参考 / 临时使用
- 收藏时间线：本周 / 本月 / 上月 / 更早

**组合视图**：基于多维度组合筛选，例如“本月收藏的高优先级设计参考”“超过30天未读的学习材料”，具体筛选器形态待定。

## 4.5 个人导航页

### 4.5.1 形态

浏览器插件，替换浏览器新标签页。

### 4.5.2 固定区域规划（方向性）

> 已确认：采用固定分区，不混排。

从上到下固定区域（顺序与是否展示待定）：
时间/搜索区 → 页面标签区 → 小组件区 → 文件夹图标区 → 书签图标区 → Docker 区

各区域占位与是否展示可在后续设计中明确。

### 4.5.3 页面标签（方向性）

- 标签按内容维度命名（如 常用/开发/阅读/灵感），每页展示对应类别内容，非按容量自动分页
- 支持水平（顶部）与垂直（左侧）两种排布，用户在设置中自定义选择
- 支持拖拽排序与重命名
- 底部页码指示点作为分页辅助，非主标签

### 4.5.4 整体风格

图标 + 图标文件夹，接近 iOS/Android 启动器：
- 每个书签以图标 + 名称展示，不显示 URL/摘要等冗余
- 同一文件夹下的书签归入“图标文件夹”，文件夹本身为聚合图标
- 点击文件夹图标展开，显示内部书签
- 网格布局，行列规整，视觉干净
- 核心原则：简洁、快速定位、像桌面启动器一样直觉化

### 4.5.5 网格布局（方向性）

- 基础网格：示例 6列 x 4行 = 24格，每书签/文件夹占 1格
- 小组件在固定小组件区内展示，不与图标混排
- 示例布局见原型，具体列行数与响应式待定

### 4.5.6 图标文件夹

- 外观：聚合图标（类似 iOS 文件夹，内部 4 小图标预览），下方显示名称
- 展开：点击以浮层 overlay 展开，显示文件夹内所有书签网格，点击外部关闭，数量多时可滚动
- 图标来源：自动取文件夹内前 4 个 favicon 拼合，也支持手动指定

### 4.5.7 书签图标

- 构成：网站 favicon 为主体，不可用时降级为首字母图标
- 名称：取 Raindrop title，支持在导航页重命名（仅影响导航页显示，不改 Raindrop 原数据），方向性

### 4.5.8 小组件（方向性）

> 固定在小组件区，优先开放核心类型。

方向性确定的核心小组件：
- 稍后读清单（显示最近 N 条未读，标题+域名，底部“查看全部”跳工作台）
- 待办/任务（checklist，数据来源待定）
- 最近访问（最近打开的书签）
- 本周统计（本周新增等）
- 便签、书架、资讯等按使用情况后续开放

每个小组件的点击行为、数据来源与更新频率待定；初期固定预设尺寸，不做自由缩放。

### 4.5.9 交互行为（方向性）

- 点击书签：在当前标签页打开
- 点击文件夹：展开浮层
- 长按/右键：菜单（编辑、移动、删除、修改图标）
- 拖拽：重排位置，可跨页/跨区拖拽（方向性）
- 空白双击：进入编辑模式
- 搜索：顶部居中搜索框，搜索所有书签，下拉列表展示，模糊匹配标题与域名（更丰富搜索见 04.8）

### 4.5.10 显示控制与隐私（已确认细化）

- **显示控制（已确认）**：存在关联；工作台侧设置“是否在导航页显示”，导航页侧决定如何显示、布局与细节编辑
  - 工作台入口：`设置 > 导航页`（或左栏快捷入口）
  - 选项：`全部显示` / `按规则显示` / `自定义勾选` / `全部隐藏`（与导航页开关互通）
  - 按规则：先做“或”逻辑（命中任一文件夹/标签/状态即显示），后续按需扩展“与”组合
  - 自定义：支持搜索筛选后再勾选（600 条场景必备），顶部显示 `已选 N / 共 600`
  - 私密项置灰默认不勾，需解锁才可勾；改动即时本地生效，`showInNav` 持久化
- **开关（已确认）**：导航页可自由开关，无需二次确认，关闭后设置与布局数据持久保留，重新打开即还原；关闭可降低性能开销（与 05.2 联动）
- **一致性**：工作台取消某文件夹/标签后导航页对应内容即时消失；导航页删除图标仅删本地快捷方式，不删工作台原数据（Docker 同理）
- **隐私**：设置中可标记私密文件夹/标签，导航页默认不展示；查看私密内容需解锁（密码/系统认证，方向性）

### 4.5.11 Docker 栏（方向性）

**概述**：导航页底部（可配置）常驻 Docker，类似 macOS Dock，放置常用图标/文件夹，始终可见，不随分页切换消失；可开关，默认开启方向。

**位置与形态**：
- 默认底部居中，可选顶部/左侧/右侧（设置中配置）
- 半透明磨砂背景条，悬浮于内容之上，不占网格格子
- 内部等间距水平排列，建议上限 12 个（超出自动缩小或溢出提示，方向性）

**内容**：
- 单个书签、图标文件夹，后续可放小尺寸小组件
- 添加：从主网格拖拽到 Docker、右键“添加到 Docker”、设置页管理
- 移除：从 Docker 拖出、右键移除、设置页管理
- 排序：支持拖拽排序，持久化

**交互**：点击行为与主网格一致；悬浮轻微放大 + tooltip；右键菜单含“在主网格中定位”

**配置项（方向性）**：启用/关闭、位置、显示名称（开/关）、最大图标数（1-16）、图标大小（小/中/大）

**数据（方向性）**：Docker 列表为导航页本地配置，不写入 Raindrop，不参与同步；清除浏览器数据需备份；主网格删除时 Docker 快捷方式同步移除，反之不影响主网格。

## 4.6 导出与备份

### 4.6.1 三档备份（方向性）

| 档位 | 目的 | 格式/内容（方向性） | 恢复效果 |
|---|---|---|---|
| **轻** | 通用迁移 | 浏览器书签 HTML、CSV、Markdown（链接+标题+标签+备注等通用属性） | 第三方工具/浏览器可读，不含个性化配置 |
| **中** | 配置还原 | 在轻的基础上 + 个性化设置为配置文件（页面标签、Docker、隐私标记、记忆偏好等） | 导入可还原核心体验 |
| **重** | 快照灾备 | 原封不动的完整快照（含本地库、使用配置、日志等，或按“备份存储”定义的完整集） | 完全还原 |

具体格式与字段待技术方案确定（已确认方向，待定细节），三档为方向分级，不作技术定稿。

### 4.6.2 导出筛选（方向性）

支持按范围筛选：全部、按文件夹、按标签、按状态、按时间范围；导出交互（弹窗/独立页）、进度、命名规则与大批量性能待定。

## 4.7 搜索（方向性）

> 按常规做法，性能不膨胀的前提下尽量丰富；以性能最优方法为准，与技术方案一起确定。

- **范围**：工作台与导航页均提供搜索；默认搜索本地标题/URL/标签/备注，支持过滤（文件夹/标签/状态/时间）
- **实现方向**：本地搜索为主，必要时可调 Raindrop API；不做全文正文索引（避免膨胀）
- **排序**：相关度 + 时间综合，支持自然语言 query（与 AI 记忆联动）
- **交互**：工作台为 ⌘K 命令面板，导航页为顶部居中下拉列表
- 具体索引策略、过滤维度与排序权重待技术方案确定，当前无额外要求，按常规最优实现。

## 4.8 首次引导（方向性）

- 首次打开引导用户完成必要配置：连接 Raindrop、配置 Skill Token、选择同步频率与隐私选项
- 引导可跳过；即使不配置，仍可通过工作台做基础录入与收藏，功能不受阻
- 具体引导步骤与 UI 待定。

## 4.9 移动端展望（方向性·已确认优先级）

- 后续考虑移动端，但以**导航页 + 轻录入**为主，不做重型整理与批量操作
- **优先级（已确认）**：浏览器插件优先（Chrome 插件大概率会做），其次响应式，App 优先级不高暂缓
- 看板、批量、工具面板等重操作仅桌面端提供
- 具体断点与交互待定。

# 05. 安全与权限

## 5.1 安全策略

### 5.1.1 AI 操作边界

| 类别 | 策略（方向性） |
|---|---|
| 禁止执行 | 删除书签、修改文件夹结构、批量操作（默认，需确认） |
| 允许执行 | 收藏新链接、搜索列出、单条修改、获取统计 |
| 限速 | 方向性示例：每分钟最多 60 次请求，连续写入超阈值触发提示，具体阈值与实现待定 |

### 5.1.2 兜底机制

- **软删除**：标记删除后保留一定周期（示例 7 天，方向性），可一键恢复
- **操作日志**：有容量与时限约束（默认初始值，用户可改，见 04.3.1），支持查看与回滚；支持导出清理、直接清理、自动定期清理、循环覆盖；默认循环存储
- **撤销条**：工作台底部撤销提示（方向性）
- **冲突处理**：本地与 Raindrop 冲突时以本地为准，提供手动合并选项（方向性）

## 5.2 性能要求

> 方向性约束，不作技术定稿；所有非核心功能以不损害核心性能为前提。

### 5.2.1 原则

- **核心优先**：导航页、工作台主视图、基础收藏/检索/同步为核心路径，性能预算优先保障核心路径
- **非核心不增负**：小组件、统计、死链/重复检测、标签治理、AI 批量/记忆等非核心功能，不得对核心路径的响应与读写造成可感知的额外负担；导航页可自由关闭以降低开销
- **可精简**：必要时可对非核心功能做降级或精简（例如减少小组件刷新频率、延后非核心计算、分页/虚拟化），但需与用户确认后执行，不自行阉割
- **容量基线（已确认）**：默认按 600 条书签收藏量设计与考核，若对性能有压力可再调整（需确认）
- **方向性**：具体阈值待技术方案确定，本文档以原则与考核方向为准

### 5.2.2 考核方向

最终以以下三类为性能考核重点（具体阈值待定，方向性）：

- **页面响应**：导航页首屏/分页切换、Docker 展开、工作台网格/列表/看板切换、整理模式两阶段切换、搜索下拉等交互的响应及时性
- **数据读写**：本地数据的读取/写入/批量操作、同步推送/拉取、导入/导出与三档备份的耗时与体感
- **同步速率监测（新增）**：记录本地 ↔ Raindrop（演进后含 SQLite）之间的数据同步速率，包括推送/拉取条数/秒、平均时延、成功率、队列长度与限频触发，供 600 条基线考核与调优

考核以实际体感与可量化记录为准，实施时再定具体场景与通过标准。
