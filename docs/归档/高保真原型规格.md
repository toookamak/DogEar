# DogEar · 高保真前端原型规格

* **日期**：2026-08-31

* **版本**：v0.1

* **状态**：✅ 已定（隔离原型，不接入正式工程）

* **关联**：PRD v0.3.6 · docs/README.md · 现状基线 `dev/nodewarden-inspired-prototype`

***

## 1. 背景与边界

现有原生原型（`dev/nodewarden-inspired-prototype`，已完成首轮验证，现已删除归档）视觉与信息架构
已获首轮验证，但交互细节和信息密度不足。本次以 Vite + React + TypeScript 重做同一隔离原型，
只解决“页面设计精化”，并通过浏览器视觉辅助定稿。

**硬边界（必须遵守）**

* 原型位于独立目录 `dev/dogear-workbench`，不写入 `apps/*`、`packages/*`。

* 不引入 UI 组件库 / 拖拽库 / 状态库 / 后端 / 真实 API / Raindrop / AI 服务。

* 数据全部为本地 mock，仅存在于浏览器内存；刷新页面后恢复初始数据。

* 不建立项目级 lint / typecheck 规范以外的工具链，不修改正式技术选型。

* 内容与品牌以 DogEar 为准，参考 nodewarden 的视觉语言与信息密度，不复制其产品内容。

## 2. 工程边界与架构

```text
dev/dogear-workbench/
├── package.json
├── index.html
├── tsconfig.json
├── vite.config.ts
└── src/
    ├── main.tsx
    ├── App.tsx
    ├── types/
    ├── data/
    ├── hooks/
    ├── components/
    │   ├── layout/
    │   ├── navigation/
    │   ├── bookmarks/
    │   ├── detail/
    │   └── feedback/
    └── styles/
```

* 工具链：Vite + React + TypeScript。

* 样式：原生 CSS，使用 CSS 变量统一设计令牌；不引入 Tailwind / shadcn / CSS-in-JS。

* 状态：React 本地状态（useState / useReducer），不引入 Zustand 等外部状态库。

* 数据与界面分离：

  * `types/`：书签、标签、文件夹、视图、同步等类型定义。

  * `data/`：虚拟书签、AI 建议、导航与标签数据。

  * `hooks/`：筛选、选中、批量操作、视图切换、反馈状态逻辑。

  * `components/`：只负责展示与事件派发。

  * `App.tsx`：组合页面区域，不承载大量业务细节。

## 3. 界面层次与视觉细节

### 3.1 工作区骨架

* 48px 顶栏、228px 可收起导航栏、可伸缩主内容区、360px 详情面板。

* 详情面板可关闭，以释放主内容宽度。

* 窄屏：主内容单列，导航与详情改为抽屉。

### 3.2 视觉语言

* 深炭黑 / 深橄榄底色，低饱和琥珀色为唯一主要强调色。

* 细描边、轻阴影、8px 圆角；避免大渐变、厚卡片与通用 SaaS 外观。

* 字体组合：Manrope（界面）、Newsreader（标题/阅读）、DM Mono（数据与元数据）。

* 高信息密度：紧凑留白、清晰分区、细边框。

### 3.3 信息密度

* 主区顶部：标题、条数、同步时间、主操作。

* 工具栏单行聚合：搜索、标签/来源筛选、排序、视图切换。

* 卡片信息次序：来源 → 标题 → 摘要 → 元数据（标签 / 文件夹 / 日期 / 阅读进度）。

### 3.4 三种视图

* **网格**：视觉浏览；站点缩略色块、标签、阅读进度。

* **列表**：高密度处理；支持复选、排序、快捷归档。

* **看板**：按“待整理 / 稍后读 / 已归档”分栏；支持模拟拖放迁移状态。

### 3.5 交互状态覆盖

* hover、选中、键盘焦点、禁用、加载骨架、搜索空状态。

* 同步成功 / 失败 / 重试、操作 Toast、批量操作栏、AI 建议状态。

### 3.6 响应式

* 桌面：侧栏 + 主内容 + 详情三栏。

* 中等宽度：详情转浮动抽屉。

* 移动端：侧栏隐藏为抽屉，筛选可横向滚动，书签单列。

## 4. 交互与数据流

### 4.1 状态模型（仅内存）

* `bookmarks`：标题、域名、摘要、来源、状态、文件夹、标签、收藏时间、阅读进度、视觉封面配置。

* `filters`：当前导航分区、搜索关键词、标签、来源、排序。

* `selection`：详情书签 ID、批量选中 ID 集合。

* `view`：grid / list / board。

* `ui`：详情显隐、侧栏显隐、同步状态、Toast 队列、加载状态。

### 4.2 关键交互

* **筛选与搜索**：匹配标题 / 域名 / 标签 / 文件夹；分区、标签、来源、排序组合过滤；清除筛选恢复当前分区默认内容。

* **选中与详情**：点击书签更新详情；列表复选不阻断详情；`Esc` 关闭详情或抽屉。

* **批量处理**：选中 ≥1 项显示批量工具栏，支持归档、稍后读、添加标签、取消选择；操作立即更新列表与统计并 Toast。

* **AI 建议**：详情面板提供接受 / 忽略 / 稍后处理；接受合并建议（标签 / 文件夹 / 状态），忽略只更新建议状态；均生成可撤销 Toast。

* **看板处理**：拖拽或列头操作迁移状态；迁移后列表 / 网格 / 统计即时同步。

* **同步反馈**：点击同步进入“同步中”，随后显示成功或失败；失败提供重试；状态栏与 Toast 记录反馈。

* **快捷键**：`Ctrl/Cmd + K` 聚焦搜索，`Esc` 关闭弹层。

### 4.3 组件边界

* `AppShell`：组合整体布局与跨区域状态。

* `TopBar`：同步触发、资料库状态、辅助操作。

* `Sidebar`：导航分区、文件夹、标签、容量显示。

* `WorkspaceToolbar`：搜索、筛选、排序、视图、主操作。

* `BookmarkGrid` / `BookmarkList` / `BookmarkBoard`：按视图渲染已过滤书签，只发事件。

* `SelectionToolbar`：批量动作。

* `BookmarkDetail`：单条书签操作与 AI 建议。

* `ToastRegion`：成功、失败、可撤销反馈展示。

* `useBookmarks`：封装筛选、选中、状态迁移与建议处理。

## 5. 验收标准

1. 网格 / 列表 / 看板可切换，切换后筛选、选中与详情保持一致。
2. 搜索、标签、来源、分区、排序可组合使用，无结果时给出明确空状态。
3. 单条与批量操作更新内容、统计和视觉状态。
4. AI 建议接受 / 忽略 / 稍后处理产生不同结果，且支持撤销反馈。
5. 看板拖拽迁移状态后，其他视图即时反映。
6. 同步具备同步中 / 成功 / 失败 / 重试完整状态。
7. 桌面、中等、移动三档布局均可操作，无溢出、重叠或不可访问控件。
8. `npm run lint`、`npm run typecheck`、`npm run build` 通过，浏览器无控制台错误。

## 6. 演示范围声明

* 所有操作仅作用于浏览器内存，刷新后恢复 mock 初始数据。

* “打开链接”“归档”“同步”“AI 建议”均为界面级模拟，不产生真实请求与持久化。

* 本规格只约束隔离原型，不改变 PRD、正式数据模型、API 或正式前端技术选型。
