========================================
十二、设计决策确认（v0.2.0）
========================================

日期: 2026-08-21
状态: 已确认

说明：基于第十一章原型 v1 评审反馈的 8 项待确认问题（#A ~ #H），
用户逐一给出了明确回复。以下按原始回复内容忠实记录。


12.1 导航页分页（对应反馈 #A）

  原问题：
    导航页分页标签：顶部横排 vs 左侧竖排？是否支持拖拽排序和重命名？

  用户回复原文：
    "横竖排布都做，做成自定义选择。支持排序和重命名"

  决策要点：
    - 水平和垂直两种排布方式都需要做，不二选一
    - 用户可以在设置中自定义选择使用哪种排布方式
    - 标签支持拖拽排序
    - 标签支持重命名


12.2 导航页区域规划（对应反馈 #B）

  原问题：
    导航页小组件：与图标混排 vs 固定区域？

  用户回复原文：
    "固定区域，后面要对图标区，文件夹图标区，小组件区和docker区做规划"

  决策要点：
    - 采用固定区域的方式，不是混排
    - 后续需要对以下区域做统一规划：
      (a) 图标区（单个书签图标的展示区域）
      (b) 文件夹图标区（文件夹图标的展示区域）
      (c) 小组件区（小组件的展示区域）
      (d) Docker 区（底部常驻快捷栏）
    - 各区域的排列顺序、是否展示、占多大空间，需要在后续设计中明确
    - 小组件区虽然暂不实现完整交互，但需要在原型中预留位置和视觉表现


12.3 工作台右侧工具面板（对应反馈 #C）

  原问题：
    右侧工具面板：常驻 vs 可折叠？工具 tab 切换 vs 垂直排列？

  用户回复原文：
    "可折叠，工具多了之后也要做分区和tab切换"

  决策要点：
    - 面板默认收起，可折叠展开
    - 工具数量增多后，需要做分区和 tab 切换来组织
    - 当前规划的 tab 分区：
      (a) 工具：死链检测、重复收藏、标签整理、域名统计等实用工具
      (b) 待处理：稍后读的紧凑列表，可在工作台内快速浏览和操作
      (c) 统计：收藏总量、各状态数量、域名 Top N、本周/本月新增等总览数据
    - 后续新增工具时，在对应分类下追加，或新增 tab 分区


12.4 整理模式保留（对应反馈 #D）

  原问题：
    独立"整理模式"页面：保留 vs 取消并融入右侧面板？
    待处理模块交互：列表+预览 vs 侧边卡片流？是否需要"标记待定"状态？

  用户回复原文：
    "保留，可以在工作区页面做分拣整理。单独的整理区首先负责是否保留，其次如何分类收纳"

  决策要点：
    - 独立的整理模式页面保留，不取消
    - 工作台页面内也可以做分拣整理（通过右侧面板的"待处理"tab）
    - 两种入口的功能分工明确：
      (a) 工作台右侧面板"待处理"tab → 在日常工作台中顺便处理，轻量、随手
      (b) 独立整理模式页面 → 专门腾出时间做系统化整理
    - 整理模式的功能分两步：
      第一步：负责判断是否保留（分拣阶段）
      第二步：负责如何分类收纳（细分拣阶段）
    - 这与两阶段分拣的设计（12.7）一致


12.5 页面预览能力（对应反馈 #E）

  原问题：
    "待定"条目是否需要标记"需要电脑前浏览"之类的上下文？
    细分拣阶段是否保留 AI 建议？

  用户回复原文：
    "这个我没有理解，页面内应该是无法直接访问页面吧，如果可以的话，可以考虑做成左右分区，左边操作整理，右边预览页面（或侧滑预览）"

  决策要点：
    - 用户确认：页面内应该是无法直接访问外部页面的（跨域限制）
    - 如果可以预览的话，期望的形式是：
      (a) 左右分区布局
      (b) 左边：操作整理区域（书签列表、操作按钮）
      (c) 右边：预览页面区域（展示书签的相关信息）
      (d) 或者做成侧滑预览（从右侧滑出预览面板）
    - 由于实际页面无法在 iframe 中加载，预览区展示替代内容：
      (a) 页面标题
      (b) URL（附"在浏览器中打开"按钮，新标签页跳转）
      (c) AI 生成的内容摘要
      (d) AI 建议的分类和标签
    - 整理模式页面和工作台待处理模块均采用此左右分区的预览形式
    - 用户需要浏览原文时，点击"在浏览器中打开"在新标签页查看
    - 查看完切回整理页面继续处理


12.6 组织维度（对应反馈 #F）

  原问题：
    新增维度是通过标签约定实现还是本地独立字段？优先做哪些？

  用户回复原文：
    "理论上是标签比较好，这样兼容Raindrop的数据格式。不过也不做限制，还没有确定是不是只把Raindrop当做备份手段之一。"

  决策要点：
    - 用户倾向于使用标签方式，理由是兼容 Raindrop 的数据格式
    - 但不做硬性限制，因为还没有确定最终是否只把 Raindrop 当做备份手段之一
    - 如果后续只把 Raindrop 当做备份手段之一，本地数据层可以做更丰富的字段和结构
    - 目前先用标签约定方式实现，保持与 Raindrop 的兼容性
    - 后续根据实际使用体验再决定是否脱离 Raindrop 的约束

  新增维度规划：

    情景维度：
      - 用途分类：学习材料 / 工作参考 / 灵感收集 / 娱乐消遣
      - 项目关联：可关联到具体项目（如"DogEar项目"、"重构计划"）
      - 优先级：高 / 中 / 低（决定处理顺序）
    
    时间维度：
      - 定期回顾：标记为"每周回顾"或"每月回顾"
      - 时效性：标记为"永久参考"或"临时使用"
      - 收藏时间线：按时间段分组浏览（本周 / 本月 / 上月 / 更早）
    
    组合视图（基于以上维度的筛选）：
      - "本月收藏的高优先级设计参考"
      - "超过30天未读的学习材料"


12.7 两阶段分拣（对应反馈 #G）

  原问题：
    两阶段分拣方案是否接受？交互形态偏好？

  用户回复原文：
    "两阶段分拣应该是合理的。不过要考虑功能的复杂度，可能有少的整理数量，也可能有很多的情况"

  决策要点：
    - 用户认为两阶段分拣是合理的方案
    - 但提出需要考虑复杂度，核心问题是：整理数量可能很少，也可能很多，两种情况都要兼顾
    - 设计要求：

      阶段一（分拣）：
        - 目的：快速判断每条是保留、删除还是待定
        - 少量场景（< 10 条）：逐条快速点击保留/删除/待定按钮，每条操作不超过 1 秒
        - 大量场景（> 10 条）：支持多选 + 批量标记，或"全部保留/全部删除"快捷操作
        - "待定"用于需要打开原网页浏览后才能判断的条目
        - 界面要紧凑、简洁、高效，所有待处理条目一次性展示，总览全局
    
      阶段二（细分拣）：
        - 目的：对标记为"保留"的条目做分类归档
        - 仅展示阶段一标记为"保留"的条目
        - 每条展示 AI 给出的分类建议（文件夹 + 标签）
        - 用户可逐条确认/修改，或批量采纳 AI 建议
        - 阶段二可选择跳过，直接用 AI 默认建议归档
    
      复杂度控制：
        - 阶段一的交互必须极简，操作门槛最低
        - 阶段二可以稍重一些，因为已经过了筛选，数量更少
        - 如果待处理数量极少（1-2 条），可以跳过阶段一直接进阶段二
        - 如果待处理数量很多，阶段一必须支持批量操作，不能逐条处理


12.8 待定条目的浏览流程（对应反馈 #H）

  原问题：
    是否支持快速打开原网页，浏览后返回继续处理？

  用户回复原文：
    "是的"

  决策要点：
    - 确认支持快速打开原网页，浏览后返回继续处理
    - 预览面板中提供"在浏览器中打开"按钮
    - 点击后在新标签页打开原文
    - 用户阅读完原文后，切回整理模式页面继续处理
    - "待定"标记帮助用户在列表中快速识别哪些条目需要浏览后决定

13.2 原型中已体现但尚未详细设计的部分

  以下在原型中有视觉展示，但交互逻辑和详细设计待补充：

  (1) 小组件
      - 原型中展示了四个小组件：稍后读、待办、最近访问、本周统计
      - 每个小组件的详细交互（点击后的行为、数据来源、更新频率）待设计
      - 小组件区域在导航页中的最终位置和大小待确认

  (2) 导航页标签的拖拽排序和重命名
      - 原型中的页面标签（常用/开发/阅读/灵感）是静态的
      - 未实现拖拽排序交互
      - 未实现双击重命名交互
      - 未实现右键菜单操作

  (3) 工具面板中的工具操作
      - 死链检测：原型中展示了"上次扫描时间"和"发现死链数"的静态数据
        实际的扫描触发逻辑、结果展示、修复建议待设计
      - 重复收藏：原型中展示了两组疑似重复的静态数据
        实际的检测算法、合并操作的具体行为（保留哪条、合并标签/备注）待定义
      - 标签整理：原型中展示了一组相似标签的静态数据
        实际的合并操作流程待设计

  (4) 左右分区预览
      - 原型中整理模式页面已实现左右分区（左侧列表 + 右侧预览）
      - 预览区展示了标题、URL、AI 摘要、AI 建议
      - 但"在浏览器中打开"的行为是模拟的（window.open），实际集成待开发

  (5) 工作台待处理 tab 与整理模式的联动
      - 工作台右侧面板的"待处理"tab 中有"进入整理模式"按钮
      - 点击后切换到整理模式页面，但数据是否同步、状态是否联动待设计

  (6) 设置页面
      - 导航页标签方向切换（水平/垂直）在设置中有下拉选项
      - 但切换后实际效果的演示未在原型中体现
      - Docker 开关已在原型中实现（点击 toggle 可隐藏/显示 Docker 栏）
      - 其他设置项（同步频率、安全策略、AI 批量上限等）的实际行为待开发时实现


13.3 原型 v2 已实现的交互清单

  为便于后续迭代，记录当前原型中已实现的交互：

  导航页：
    - 时间实时更新
    - 搜索框（静态，无实际搜索）
    - 页面标签切换（常用/开发/阅读/灵感）
    - 小组件展示（稍后读数字、待办数字、最近访问列表、本周统计）
    - 文件夹图标点击 → 展开浮层（显示文件夹内书签图标）
    - 浮层点击外部关闭
    - Docker 栏图标悬浮显示名称提示
    - Docker 栏在设置中可开关

  工作台：
    - 左侧导航栏：待处理/收藏/最近 + 文件夹树 + 标签 + 导出/日志/设置
    - 顶部：搜索框 + 视图切换（网格/列表/看板）+ 排序 + 工具面板开关
    - 网格视图：卡片展示，悬浮显示操作按钮，点击选中（批量选择）
    - 列表视图：紧凑行展示，点击选中
    - 看板视图：三列展示（未读/在读/已整理）
    - 批量操作栏：选中卡片后底部弹出
    - 右侧工具面板：可折叠，三个 tab（工具/待处理/统计）
    - 工具 tab：死链、重复、标签、域名统计的静态展示
    - 待处理 tab：紧凑列表，悬浮显示操作按钮，点击高亮
    - 统计 tab：数据卡片 + 数值列表

  整理模式：
    - 两阶段 tab 切换（① 分拣 / ② 细分拣）
    - 阶段一：左侧紧凑列表 + 右侧预览面板
    - 左侧列表：点击条目切换预览，每条三个按钮（保留/删除/待定）
    - 操作后左侧显示状态标记（绿色保留/红色删除/黄色待定）
    - 可撤销操作
    - 批量操作：全部保留/全部删除/全部待定
    - 底部统计已操作数量
    - 保留至少 1 条后"进入细分拣"按钮激活
    - 阶段二：展示保留条目的 AI 建议，每条有采纳/修改按钮
    - 阶段一中点击条目 → 右侧预览：标题、URL、AI 摘要、AI 建议、"在浏览器中打开"按钮

  弹窗：
    - Skill API：自描述接口 JSON 示例
    - 导出：范围选择 + 格式选择 + 导出按钮
    - 设置：Docker 开关、标签方向、同步配置、安全配置
    - 日志：操作记录表格，带撤销/恢复链接

  全局：
    - 顶部标签切换三个主页面（导航页/工作台/整理模式）
    - Toast 通知（带撤销入口）
    - 键盘快捷键：整理模式中 Enter/E/D/S/←→（仅在整理模式页面内有效）
