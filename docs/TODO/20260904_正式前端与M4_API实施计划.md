> 文档状态：评审中 → 已获执行确认（2026-09-04）
> 计划日期：2026-09-04
> 适用范围：M4 正式前端工作台、M4 后端 API 补齐
> 视觉依据：根目录 `DESIGN.md`（唯一视觉源；专有字体缺失回退系统栈，本期浅色无暗色）

## 一、目标与边界

### 目标

将 `apps/web` 从当前单文件最小页面推进为可使用的 M4 正式工作台，并让页面按照 `docs/API结构表.md` v1.1 使用真实后端接口。前端以根目录 `DESIGN.md` 为唯一视觉源，参考 `dev/dogear-workbench` 的信息架构和交互方式，但不复用 mock 数据作为正式数据源。

### 本阶段包含

- 登录、会话检查、退出登录

- 工作台应用壳层（采用 wouter 轻量路由，页面间 URL 直达）

- Inbox 与全部书签列表

- 书签搜索、分页、筛选和排序展示；⌘K 命令面板（端侧 MiniSearch 索引，按标题/URL/标签/备注检索并跳转/选中）

- 列表/网格视图切换

- 书签详情面板

- 保存、编辑、标星、状态修改、移动文件夹、挂载/移除标签和场景；保存面板含 note/intent/important/private 可选字段

- 批量处理

- Scene、Folder、Tag 的基础管理与选择

- 回收站查看、恢复、永久删除和清理入口

- AI 建议查看、接受、延后、忽略；四个落点（输入时/整理时/Inbox 内/未整理详情）以占位 UI 排入，尽量呈现完成态，无模型时返回空建议不崩

- 操作日志和基础设置展示

- Job 列表及重试/取消入口的前端接线

- M4 API 结构表中缺失字段或回执的补充、实现和测试

### 本阶段不包含

- Raindrop 同步及 `/channels/*`

- S3/WebDAV 备份、恢复、导入导出

- 快照文件上传、下载和替换

- 导航页规则

- 离线缓存、Dexie/IndexedDB 镜像
- Skill 批量、删除和默认能力策略变更
- API 表 v1.1 明确禁止的 `/channels/*`、`/backup`、归档内容传输和 `/navigation/rules`
- 修改 `wiki/`

- 修改根目录 `DESIGN.md`

- 引入新的 UI 组件库或生产依赖（**例外**：经用户确认仅放行 `wouter` 轻量路由与 `MiniSearch` 端侧检索两个生产依赖，其余边界不变）

## 二、实施顺序

1. 盘点 `docs/API结构表.md`、`apps/server/src/app.ts`、`packages/shared/src/contracts.ts`、`packages/db/src/repository.ts` 的实际差异。
2. 先补齐 M4 API 契约和后端测试，再实现缺失接口；不擅自增加 M5/M6 路由。
3. 把正式前端按职责拆分为 API 客户端、类型、页面、业务组件和样式模块。
4. 先完成工作台主链路：认证 → Inbox/书签列表 → 保存 → 详情 → 修改 → 刷新。
5. 再接入筛选、批量、组织维度、回收站、建议、日志、设置和 Job。
6. 每个功能单元先写失败测试，再写最小实现；完成一个单元后运行对应测试、lint、typecheck。
7. 对照 `DESIGN.md` 检查视觉、响应式、焦点状态、空状态、加载状态和错误状态。
8. 代码与文档分开提交；每个阶段更新根目录 `CHANGELOG.md`。

## 四、后端 API 工作包

### API-1：契约盘点

对照结构表 v1.1 逐项核对：请求字段、可选字段、分页、空值、成功状态码、错误码、鉴权、软删除规则和日志要求。输出缺口清单，只允许 M4 范围内的缺口进入本轮。

当前已识别的重点缺口包括：列表与搜索的 `limit/cursor/nextCursor`、统一错误回执、创建完整字段与 `Idempotency-Key`、更新 `version` 冲突、批量更新回执、访问记录请求语义、回收站分页和状态、Scene/Folder/Tag Schema、建议状态幂等、日志分页、设置白名单与类型、Skill 能力更新、Skill 用量、Job 状态校验，以及统计和 Skill 列表的字段语义。

### API-2：共享 Schema 与回执

为书签列表、搜索、批量更新、Scene/Folder/Tag、回收站、建议、日志、设置、Skill 能力/用量和 Job 补齐可复用 Schema。统一约定 Inbox 使用 `bookmarks` 加 `nextCursor`，其它列表使用 `{items,nextCursor}`；所有错误使用 `error.code`、`error.message`，不得在前端依赖自由文本判断错误类型。

### API-3：路由和仓库接线

按结构表 v1.1 实现缺失路由，复用现有仓库方法和鉴权中间件。书签创建需支持完整字段、写入操作日志和 24 小时幂等；更新需校验 `version` 并返回冲突详情；列表需稳定排序和不透明游标；批量、回收站、组织资源、建议、设置、能力、用量和 Job 需遵守各自错误及状态约定。不得新增备份、同步或快照文件路由。

### API-4：后端验证

至少覆盖：未登录、非法参数、统一错误体、分页边界和稳定排序、幂等重放、版本冲突、批量上限、场景删除冲突、软删除与恢复、建议状态变化、设置敏感字段过滤、Skill 能力关闭、用量回执、Job 操作状态和错误回执。运行根目录 `pnpm test`、`pnpm lint`、`pnpm typecheck`。

### API-5：契约同步与确认门

API 表仍处于评审中。每次补写或调整 API，必须同时更新本计划书中对应的工作包、前端接线清单、验收链路和待确认项，并在提交前检查两份文档的版本、日期和范围一致。未获得用户对 API v1.1 与本计划的确认前，不修改 `apps/server`、`packages/shared`、`packages/db` 或 `apps/web` 正式代码。
## 五、正式前端工作包

### WEB-1：应用壳层和认证

保留当前登录 API 和 Cookie 会话行为，拆出 LoginPage、Session Hook、AppShell、Sidebar、TopBar、StatusBar。所有页面共享加载、错误和退出登录处理。

### WEB-2：书签主链路

接入 `/api/inbox`、`/api/bookmarks`、`/api/bookmarks/:id`、`POST /api/bookmarks` 和访问记录接口。实现保存链接、列表、空状态、加载状态、错误重试和打开原链接前的访问打点。

### WEB-3：搜索、筛选和视图

接入 `/api/bookmarks/search` 与列表 query，支持 `q`、status、scene、folder、tag、important、source、limit、cursor。筛选状态放在页面状态中，接口请求集中放在 API 模块，组件只负责展示和交互。

### WEB-4：详情和组织

接入书签 PATCH，支持标题、摘要、备注、标星、私密、状态、文件夹、标签和场景。Scene/Folder/Tag 选择器只提交结构表允许的字段；修改成功后更新当前详情和列表，失败时保留表单输入并显示错误。

### WEB-4.5：⌘K 命令面板

顶部搜索框聚焦唤起命令面板；加载当前页可见列表数据构建端侧 MiniSearch 索引（标题/URL/标签/备注），输入即筛并跳转/选中目标书签；命令面板与列表搜索结果以后端一致为准，端侧索引为入口加速。Esc 关闭、无结果有提示；不引入自研倒排。

### WEB-4.6：保存面板扩展与 AI 建议四落点占位

保存表单展示 note/intent/important/private 可选字段（对应 create 完整字段）。AI 建议四个落点（输入时/整理时/Inbox 内/未整理详情）以统一 Suggestion 模型排入占位 UI，尽量呈现完成态：展示建议来源与建议动作，确认后才写结构，无模型/后端返回空时显示空建议不崩。不做看板式复杂动效。

### WEB-5：批量、回收站和建议

实现多选工具栏与批量 PATCH；回收站接入列表、恢复、硬删和清理；删除、恢复、清空等不可逆或高影响操作使用二次确认。建议接入查看、接受、延后和忽略，接受后刷新相关书签归属。

### WEB-6：日志、设置和 Job

实现日志列表、基础设置读取/保存、Skill 能力开关和用量展示、Job 列表、重试和取消。不得在页面展示服务端口令、Skill Token 或其他敏感信息。页面接线以 API v1.1 的统一列表回执、错误码、能力设置回执、用量字段和 Job 状态机为准；未明确的交互细节可参考原型对应设置区块，但不接入原型中的 M5/M6 mock 设置。

### WEB-7：视觉和响应式验收

按照 `DESIGN.md` 对照检查暖色背景、字体层级、边框、圆角、按钮、焦点状态、hover、空状态、错误状态、移动端单列布局和触控尺寸。不得从原型或其他页面另立颜色和组件规则。

## 六、测试和验收

### 自动化命令

```powershell
pnpm test
pnpm lint
pnpm typecheck
pnpm build
```

### 验收链路

1. 未登录访问工作台被引导到登录页。
2. 登录后可看到 Inbox、未推送数量和空状态/列表状态。
3. 保存 URL 后书签出现在 Inbox，刷新后数据仍存在。
4. 搜索和筛选结果与 API 参数一致，分页可继续加载。
5. 打开链接会写入访问记录，原链接仍正常打开。
6. 编辑书签、场景、文件夹、标签后，详情和列表状态一致。
7. 批量操作只影响选中项，超过 100 条得到稳定错误。
8. 删除、恢复和永久删除均有二次确认，回收站状态正确。
9. 建议处理、日志、设置和 Job 操作可显示成功或稳定错误。
10. API 错误不会依赖服务端英文文本，401 会回到登录态。
11. 页面在移动端、平板和桌面宽度下没有横向溢出。
12. M5/M6 页面没有被错误接入 M4 API，也没有生成未批准的新路由。

## 七、提交和停机条件

- 每个独立工作包完成后先运行对应测试、lint、typecheck，再提交代码。

- API 契约/后端提交与前端提交分开。

- 每次提交前在 `CHANGELOG.md` 最上方增加日期、应用版本和一句变更说明。

- 不提交 `.env`、密钥、本地数据库、构建产物和测试素材。

- API 结构表发生补写时，必须在同一文档环节同步更新本计划书，并检查 API 表与计划书的版本、范围、验收和确认门。

- 发现 API 结构表与现有实现冲突、需要改数据库 Schema、需要新增 M5/M6 路由、或需要改变公共 API 返回结构时，立即暂停并请求确认。
