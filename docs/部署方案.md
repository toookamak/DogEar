# DogEar 部署方案

> **版本**：v1.0（2026-09-01）
> **关联**：PRD v0.3.8（07 章部署方向落定）；《技术方案路线》v0.3（真源变更）；《同步引擎细化》v0.2（增量探测与历史机制）
> **状态**：✅ 已定（本轮技术方案讨论的落地文档之一）

***

## 0. 一句话总览

同一套服务端代码，两种部署轨：**Cloudflare Workers（默认轨，一键部署）** 或 **Docker（本地轨）**，部署二选一、互不级联；所有平台差异由配置抽象层吸收，业务代码不感知。

```
浏览器（扩展 / 工作台 Web）
  ├── IndexedDB（本地缓存层，读永远优先走这里）
  └── ⇅ 只连一个服务端（用户部署时二选一）
        ├─ 轨 A：Cloudflare Workers + D1（云端，任何设备可达，默认推荐）
        └─ 轨 B：Docker + SQLite（本地 / NAS，局域网零延迟）
```

**注意**：两轨是替代关系不是级联关系。不存在"Cloudflare 回连本地服务"的链路，Workers 不会访问用户家庭网络。

***

## 1. 设计原则

1. **零前置设置**：部署命令只有一条（`npm run deploy` 或 `docker compose up -d`），无需在命令行配置任何密钥。所有个性化配置（访问密码、Raindrop token）通过部署后首次打开页面的**初始化向导**完成。
2. **同构服务端**：业务逻辑（Hono 路由、同步引擎、Skill API）完全共用，平台差异收敛到两个抽象层：

   - `packages/db`：存储适配器接口（D1 适配器 / SQLite 适配器）

   - `dogear.config.ts`：应用配置 schema（由 `packages/shared` 统一导出类型，两轨共用同一份校验逻辑）
3. **数据自持**：用户随时可导出完整数据（HTML/CSV/MD 三档备份），Workers 轨另可用 D1 导出、Docker 轨可直接复制 SQLite 文件。不锁定在任何平台上。
4. **公网安全**：Workers 轨默认暴露在公网 URL，鉴权是初始化的一部分而非可选项（见 §4）。

## 2. 轨 A：Cloudflare Workers（默认轨）

### 2.1 组件与绑定

| 组件           | 用途                             | 预置方式                             |
| ------------ | ------------------------------ | -------------------------------- |
| Worker       | Hono 应用（路由 / 同步引擎 / Skill API） | `wrangler.jsonc` 预置              |
| D1 数据库       | 真源存储（schema 与 SQLite 同构）       | 部署时 `wrangler d1 create` 自动创建并绑定 |
| Cron Trigger | 同步引擎定时触发（推送队列 + 增量拉取）          | `wrangler.jsonc` 预置 1 条          |
| KV           | 预留但不默认：默认不创建、不绑定               | 未来多实例/边缘缓存场景按需启用                 |

### 2.2 一键部署流程

```bash
# 用户唯一需要执行的命令
npm run deploy
# = wrangler login（首次，浏览器授权）+ wrangler deploy（含 D1 创建/migrate/绑定）
```

1. `wrangler login`：浏览器跳转 Cloudflare 授权（仅首次）。
2. `wrangler deploy`：自动完成 D1 建库 → 执行 migrations → 绑定 Worker → 上线。
3. 部署完成输出 URL，用户浏览器打开即进入**初始化向导**（见 §4）。

### 2.3 免费额度足够性（已按 2025 核实限额计算，600 条基线）

| 资源            | Free 限额    | 本项目例行消耗/天                        | 占比   |
| ------------- | ---------- | -------------------------------- | ---- |
| Workers 请求    | 100,000/天  | cron 触发 ≤288 + 用户浏览 + 转发 < 5,000 | \~5% |
| Workers CPU   | 10ms/请求    | 同步操作均为轻量 IO，单次 <5ms              | 安全   |
| D1 存储         | 500MB/库    | 600 条书签 + 队列 + 日志 < 5MB          | \~1% |
| D1 读取         | 5,000 万行/天 | 主要为 IndexedDB 缓存刷新查询             | <1%  |
| Cron Triggers | 5 条        | 1 条                              | 20%  |

**结论：按 Free 档设计，不需要 Paid 计划**（Paid 的 5min CPU / 10GB 对本项目是巨大浪费）。

## 3. 轨 B：Docker（本地轨）

### 3.1 组件

| 组件 | 用途 |
| --- | --- |
| 容器 | Bun 运行 Hono 应用（内置 `bun:sqlite`，零原生依赖，支持 ARM/x86），采用多阶段构建，最终镜像 <150MB |
| SQLite | 数据卷挂载（`/data/dogear.db`），作为服务端真源存储 |
| 快照 | 容器内每日滚动快照 SQLite 文件（保留 N 份，默认 7，可配），作为 Docker 轨的恢复兜底 |
| 定时任务 | 进程内调度器，与 Workers Cron 共用同一同步引擎入口 |

### 3.2 部署流程

```bash
docker compose up -d
# 打开 http://localhost:<port> 进入同一个初始化向导
```

`docker-compose.yml` 约定：

- 端口、数据卷路径、快照保留份数均在卷映射 / 环境变量层配置；

- 应用配置同样读取 `dogear.config` 运行时值（向导写入库，优先级高于环境变量默认值）；

- 不要求挂载任何密钥文件。

***

## 4. 初始化向导（两轨共用）

部署后首次访问时强制进入，**不完成初始化无法使用任何 API**（中间件拦截）。

| 步骤 | 内容                | 说明                                                           |
| -- | ----------------- | ------------------------------------------------------------ |
| 1  | 设置访问密码            | 服务端 AES-GCM 派生密钥加密存库；此后所有 API（含 Skill API）要求会话或 Bearer Token |
| 2  | 粘贴 Raindrop token | AES-GCM 加密存库（`settings` 表），全程零命令行                            |
| 3  | 首次全量导入            | 按《同步引擎细化》v0.2 的增量协议做首次全量拉取（唯一一次全量），带进度反馈                     |

**鉴权二选一**（本轮已定）：

- 默认：访问密码（向导设置）；

- 轨 A 可选：用户在 Cloudflare 后台启用 Zero Trust / Access 后，可在设置中**关闭密码鉴权**，由 Access 承担访问控制。两者互斥，不支持叠加。

Raindrop token 存储方式为**向导录入 + 加密存库**，不提供 wrangler secret 路径（避免命令行步骤）。

***

## 5. 配置抽象（dogear.config）

单一 schema（`packages/shared` 导出类型），两轨共用；平台绑定（wrangler.jsonc / docker-compose.yml）与应用配置（dogear.config）严格分离，互不混写。

```ts
// dogear.config 的运行时值存于 settings 表，向导与设置页读写；以下为默认值
{
  sync: {
    pushIntervalSec: 30,        // 推送合并窗口
    pullIntervalMin: 5,         // 增量拉取频率（5/15/手动 三档）
    pullOnOpen: true,           // 打开页面时触发一次增量比对
    maxRetries: 3,              // 429 重试上限
    backoffCeilSec: 300,        // 指数退避封顶
  },
  history: {
    softDeleteDays: 7,          // 软删除保留窗口
    snapshotKeep: 7,            // Docker 轨快照滚动份数（Workers 轨用 D1 Time Travel，不占此配置）
  },
  log: {
    retentionCount: 5000,       // operation_log 上限
    retentionDays: 30,
  },
  auth: {
    mode: 'password' | 'cf_access',   // 二选一；cf_access 仅轨 A 可用
  },
}
```

## 6. 迁移与数据自持

| 场景 | 路径 |
| --- | --- |
| Workers → Docker | 在迁移页导出统一 JSON bundle，在 Docker 迁移页上传并校验后事务导入 SQLite |
| Docker → Workers | 在迁移页导出统一 JSON bundle，在 Workers 迁移页上传并校验后事务导入 D1 |
| 日常备份 | Web 界面导出 JSON bundle；轻/中/重三档备份仍可按需导出 HTML、CSV、MD 或完整快照 |

JSON bundle 包含 schema 版本、全表数据与必要配置。导入前执行版本兼容性校验，确认后以事务写入；敏感配置保持加密状态。

## 7. 本轮已定决策记录（供后续文档对齐）

| # | 决策             | 结论                                                                           |
| - | -------------- | ---------------------------------------------------------------------------- |
| 1 | 部署双轨           | Workers 默认轨 + Docker 本地轨，二选一互不级联                                             |
| 2 | 公网鉴权           | 访问密码默认；启用 Cloudflare Access 时可关闭密码功能，二选一                                     |
| 3 | Raindrop token | 向导录入 + AES-GCM 加密存库，零命令行                                                     |
| 4 | 历史与撤回          | 软删除 7 天 + D1 Time Travel（7/30 天）/ SQLite 滚动快照兜底，限定时间范围控制资源占用；不做 UI 级单条撤销     |
| 5 | 拉取频率           | 默认 5 分钟，后台可配置（5/15/手动 三档）                                                    |
| 6 | 真源             | 服务端为真源（D1/SQLite），IndexedDB 仅为缓存（推翻技术方案路线 v0.2 的"前端直连 Raindrop"路线）           |
| 7 | 增量探测           | 例行先查 `/collections` 的 `lastUpdate`（1 次请求），有变化才拉对应 collection 详情；全量仅首次导入与每周兜底 |
