## §0 为什么上一轮「不明显」

v0.7.48 做的是**等值归位**：把语义已正确的地方换成 token、把散值并档。它消除的是「不一致」，但不制造「视觉层级差异」——因为刻度本身没有层级可言（见 §1.1），且完全没有触碰侧栏。

- 做对了：19 个字号散值 → 7 档；控件高度五档混排 → 32px 统一；原生控件接管
- 漏掉了：刻度自身仍断裂；71 处硬编码未收；侧栏一行未动

本轮补这两块。

## §1 根因（证据均带 file:line）

### 1.1 间距刻度自身断裂（核心）

`tokens.css:89-94`：

| Token | 值 | 是否 4px 倍数 |
| --- | --- | --- |
| `--space-1` | 4px | 是 |
| `--space-2` | 8px | 是 |
| `--space-3` | 12px | 是 |
| `--space-4` | 16px | 是 |
| `--space-5` | **22px** | **否**（4×5.5） |
| `--space-6` | **30px** | **否**（4×7.5） |

整个体系里唯一破格的两档正是最高的两档。相邻档差：+4 / +4 / +4 / **+6** / **+8**。

后果：竖向堆叠的区块间距**不可预测**。16px 与 22px 只差 6px，在 13px 正文旁读不出「有意为之」，只读作「没对齐」——这是「太密集或太疏松显得异常」的直接来源。

### 1.2 两套间距体系并行，且同名不同义（维护陷阱）

| 体系 | 定义位置 | 档数 | 引用数 | 语义 |
| --- | --- | --- | --- | --- |
| `--space-1..6` | `tokens.css:89-94` | 6 | **199** | 序号刻度 |
| `--spacing-*` | `tokens.css:176-193` | 17 | **12** | 像素刻度（值即名字） |

两者**名字形状相同、数值相差 4~5 倍**：

| 写法 | 值 | 对照 |
| --- | --- | --- |
| `--spacing-2` | 2px | `--space-2` = 8px（4×） |
| `--spacing-3` | 3px | `--space-3` = 12px（4×） |
| `--spacing-4` | 4px | `--space-4` = 16px（4×） |
| `--spacing-6` | 6px | `--space-6` = 30px（**5×**） |
| `--spacing-12` | 12px | `--space-12` 不存在 |

真实现场：`app.css:3593` `.chips-row { gap: var(--spacing-6) }` = **6px**；若笔误成 `var(--space-6)` 则变 **30px**。这类笔误不报错、不中断构建，只在界面上多出 24px 空白。间距不一致就是这样一层层攒出来的。

### 1.3 71 处硬编码 px 间距，仅 4 处含 token 变量

`app.css` 中 `padding|margin|gap` 带字面 px 的声明共 **71** 条，含变量的只有 4 条。

「差 1px 的邻居」（同类控件、多种写法）：

| 声明 | 出现次数 | 代表位置 |
| --- | --- | --- |
| `padding: 2px 9px` | 4 | L906 状态 pill、L1429、L1688、L2128 附近 |
| `padding: 2px 8px` | 2 | L1821、L1854 |
| `padding: 1px 7px` | 2 | L1656、L2055 |
| `padding: 2px 6px` | 1 | L1462 |
| `gap: 7px` | 6 | L284 品牌、L1387、L1589、L2061 … |
| `gap: 5px` | 7 | L905、L1427、L1814、L1969 … |
| `gap: 9px` | 1 | L2127 |

同一个「小徽标内衬」在 6 / 7 / 8 / 9px 之间摇摆，不是取舍，是逐次手写累积。

机械痕迹一处：`app.css:3187` `.auth-card { padding: var(--space-6) var(--space-6) var(--space-6) }` —— 三值全同。

### 1.4 页面级主留白不统一（跨页可见）

| 页面 | 声明 | 水平留白 |
| --- | --- | --- |
| 工作台 | `.toolbar:1139`、`.bookmark-area:2384` | **30px** |
| 设置页 | `.settings-layout:1063` `padding: var(--space-4)` | **16px** |
| 组织管理页 | `.org-content--padded:3598` `padding: var(--spacing-16)` | **16px** |

三页之间切换时内容左边缘水平跳动 14px。这是最容易察觉的一条，因为它是**跨页对比**。

### 1.5 竖向节奏不统一，且工具栏顶到边

| 区块 | 声明 | 底间距 |
| --- | --- | --- |
| `.toolbar:1139` | `padding: 0 var(--space-6) var(--space-4)` | 16px |
| `.bookmark-area:2384` | `padding: 0 var(--space-6) var(--space-5)` | 22px |
| `.filter-row:2451` | `padding: 0 var(--space-6) var(--space-3)` | 12px |
| `.save-form-wrap:2455` | `padding: 0 var(--space-6) var(--space-3)` | 12px |

`.toolbar` **上留白为 0**，紧贴 48px 顶栏的 1px 底边，无呼吸空间 → 工具区顶部过密、书签区底部过松。

`.bookmark-area[data-density="compact"]:2390` 同一条轴向左距还从 30px 变 16px，切换信息密度会让整列内容横向跳动。

### 1.6 侧栏「原始」的六条实体原因

| # | 现象 | 证据 |
| --- | --- | --- |
| 1 | **零图标**：侧栏是全站唯一没有图标语言的一级导航，而顶栏/工具栏已在 v0.7.48 换成内联 SVG | `Sidebar.tsx:90/120/146/182/198` 直接渲染 `{label}` / `{name}` |
| 2 | **分组标题与条目权重几乎相同**：标题 11px `--faint`、条目 13px `--muted`，同属灰阶、只差 2px | `app.css:450-460` vs `514-533` |
| 3 | **四个分组之间无分隔**：只有 `margin-bottom: 16px` 空白 | `app.css:444-447` |
| 4 | **缩进关系反了**：标题左缘 12+8=**20px**，条目左缘 12+12=**24px** | `app.css:453` vs `520` |
| 5 | **条目行高不在控件刻度上**：`padding: 7px 12px`（硬编码 7px）→ 约 27px，与 32px 控件族不同档 | `app.css:520` |
| 6 | **当前项信号过弱**：`--amber-soft` 仅 13% 橙压在 `#f7f7f5` 上几乎不可见，2px 左条是唯一信号 | `app.css:541-545`、`485-490` |

## §2 方案 A · 间距体系重建（不涉及布局）

### 2.1 刻度归到 4px 网格，延伸至 8 档

| Token | 现在 | 改为 | 变化 |
| --- | --- | --- | --- |
| `--space-0`（新增） | — | **2px** | 承接原 `--spacing-2` 的「微衬」语义 |
| `--space-1` | 4px | 4px | — |
| `--space-2` | 8px | 8px | — |
| `--space-3` | 12px | 12px | — |
| `--space-4` | 16px | 16px | — |
| `--space-5` | 22px | **24px** | 归网格（+2px） |
| `--space-6` | 30px | **32px** | 归网格（+2px） |
| `--space-7`（新增） | — | **48px** | 页面级大留白 |
| `--space-8`（新增） | — | **64px** | `.loading` 居中留白 |

相邻档差变为 +4/+4/+4/+8/+8/+16/+16，呈可预测的倍增。

### 2.2 废弃 `--spacing-*` 旧体系（12 处逐条映射）

> ⚠️ 逐条映射**不能批量替换**：`--spacing-3`=3px ≠ `--space-3`=12px，批量替换会把区块间距放大 4 倍。必须按上表逐处处理。

### 2.3 71 处硬编码归位

规则：
1. **归位**：映射到最近的 `--space-*` 档（上取整，宁可略松不略紧）
2. **例外白名单**（保留字面值，写入 DESIGN.md）：
   - `0`
   - `1px` / `2px`：描边式微调、`inset` 定位、勾选键内部对齐
   - `auto`
   - 空状态与加载态的**居中大留白**（`.not-found` 的 `70px 20px`、`.empty-state` 的 `80px`）—— 构图值，非节奏值
3. **「差 1px 邻居」归一**：`2px 9px` / `2px 8px` / `1px 7px` / `2px 6px` → 统一 `2px var(--space-2)`；`gap: 7px / 5px / 9px` → 统一 `var(--space-2)`（8px）或 `var(--space-1)`（4px），按元素体量取
4. `.auth-card:3187` 三值同值 → 单值 `var(--space-6)`

### 2.4 统一页面主留白与竖向节奏

| 项 | 现在 | 改为 |
| --- | --- | --- |
| 工作台水平留白 | 30px | `var(--space-6)` = 32px |
| 设置页水平留白 | 16px | `var(--space-6)` = 32px |
| 组织管理页水平留白 | 16px | `var(--space-6)` = 32px |
| `.toolbar` 上留白 | **0** | `var(--space-4)` = 16px |
| 竖向条底间距 | 12 / 16 / 22px | 统一 `var(--space-4)` = 16px |
| `.bookmark-area[data-density=compact]` 水平 | 16px | `var(--space-6)`（只收窄网格，不收窄页边） |

→ 跨页切换内容左边缘不再跳动；同页竖向节奏可预测。

## §3 方案 B · 侧栏改造（三向待裁决）

三向**共同**改动：
- 一级导航（Inbox / 书签）与底部设置**补图标**（`Icon.tsx` 新增 `inbox` / `bookmark` / `layers` / `folder` / `tag` / `settings`）
- 条目行高归到 **30px**、圆角 `--radius-lg` 6px、内边距 `0 var(--space-2)`
- 分组标题与条目左缘对齐（同取 8px 内衬，取消 §1.6-4 的 4px 反缩进）
- 当前项提权：保留 `--amber-soft` + 左条，文字转 `--text`，计数转 `--amber-strong`
- 分组标题带 mono 计数与（标签组的）「管理」入口

差异在**分组如何被「框」出来**：

| | A · 分隔线 + 图标 | B · 分组卡片 | C · 扁平主导航 + 维度卡片 |
| --- | --- | --- | --- |
| 分组容器 | 无容器，组间 1px 淡分隔线 + 间距 | 每组成白卡（`--panel` 底 + `--line` 边 + 6px 圆角 + 4px 内衬） | 主导航扁平无容器；三个维度组用白卡 |
| 「模块感」强度 | 中 | 强 | 中强 |
| 与 Notion 调性 | 一致 | 偏离（接近 Linear / Height） | 折中 |
| 风险 | 可能仍显平 | 228px 内堆 4 张卡易显琐碎 | 两套形态并存需克制 |

**推荐 C**：一级导航是「去哪」（高频、路径性），保持扁平 + 图标，符合 Notion 式克制；场景 / 文件夹 / 标签是「有什么」（集合性），用白卡框出来，直接回应「不同模块没有效果」。

## §8 未验证与已知偏差

**未验证**：

- 浏览器人工目视明暗两套（沙箱内 `agent-browser` 启动 Chromium 被 SIGTERM 强制终止，全部结论来自源码与设计源逐行比对）
- `--space-5` 由 22px→24px、`--space-6` 由 30px→32px 的**全局连带**：所有引用点各 +2px，需核对是否在窄视口下溢出（尤其 `.auth-card`、`.not-found`）
- 侧栏在 228px 宽度内的实际换行/截断表现

**已知偏差**：条目行高 30→32px（见 §7）。

**后续可合并的债**：`.btn--pill` 与 `.btn--ghost` 规格已趋同；另注意 `.btn--pill` 在 `app.css` 中位于 `.btn--primary` **之后**且同为单类特异性，故 `btn--pill btn--primary` 组合会被 pill 的 `background:none` 吃掉实底橙——同步浮条的「推送」按钮已就地用两类选择器保底，全局顺序未动（那会波及数十处调用点）。若后续合并按钮族，此陷阱应一并消除。
