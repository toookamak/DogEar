- 判定依据优先顺序：需求总纲（PRD，唯一需求源）→ 技术总纲正文已决表述 → 既有模块文档细部 → 需实测/专题论证的才保留为待验证。

## 2. T-1 判定：Docker 运行时与真源 SQLite 驱动

### 2.1 依据链

- 技术总纲 §9.1 表格：Track B 运行时「Bun 或 Node 进程」、真源 DB「bun:sqlite / better-sqlite3」。

- §9.2 开发环境：本地服务 `@dogear/server` 走「Hono；SQLite 走本地文件」——**本地开发形态与 Track B 同构**，此判定同时决定本地开发默认栈。

- 依赖清单 §4.3 末尾：`tsx / bun` 双列为本地开发运行；真源驱动由 `packages/db` 启动时按环境注入（§9.1 共同约束）。**真源 DB 与运行时之间不是正交选择**：

  - `bun:sqlite` 只存在于 Bun 运行时（内置、零依赖）；

  - `better-sqlite3` 是 Node 原生模块（需要编译/预编译二进制，Track B 与本地开发都要 Node 运行时）。

### 2.2 小型基准实验（2026-09-03 已跑）

> 位置：临时目录（`docs/modules/.bench-t1`，已加入 `.gitignore`，不随仓库提交）。仅做**冒烟 + CRUD 量级对照**，环境：本机 Windows / Node v22.23.1 / Bun 1.3.10 / better-sqlite3 v13.0.3（预编译）。
>
> 脚本同构（5k 行事务插入 + 1k 点查 + LIKE 扫描 + 500 事务更新 + 200 事务删除），三次实测取中位段。更新/删除必须走事务才有意义——非事务下两者均因逐条 fsync 掉到 1.7\~4.8 s 量级，此现象**与驱动无关**，仅提示业务写入要走事务（Drizzle 默认即如此）。

| 维度          | bun:sqlite（Bun 1.3.10）             | better-sqlite3（Node v22.23.1，v13.0.3 预编译） | 备注                                 |
| ----------- | ---------------------------------- | ----------------------------------------- | ---------------------------------- |
| 安装          | Bun 内置，无需 `npm install`            | 需安装；v13 预编译二进制，装包成功、0 漏洞                  | 依赖方：Bun 少一个原生依赖；Node 侧需匹配 Node ABI |
| 冒烟 CRUD     | ✅ 全通（建库/建表/插/查/改/删/事务）             | ✅ 全通（同左）                                  | 两者 API 均为同步，写法相近                   |
| 插 5k 行（事务）  | 约 22 ms                            | 约 25 ms                                   | 差异 <15%，单机量级不构成决策主因                |
| 点查 x1000    | 约 38 ms                            | 约 39 ms                                   | 基本持平                               |
| LIKE 扫描     | 约 0.5 ms                           | 约 0.6 ms                                  | 基本持平                               |
| 改 500 行（事务） | 约 11 ms                            | 约 12 ms                                   | 基本持平                               |
| 删 200 行（事务） | 约 10 ms                            | 约 10 ms                                   | 基本持平                               |
| 驱动 API 差异   | 内置 `Database`；无 `.raw()` 等价物，类型为内置 | 返回原生行对象；`integer` 安全需 `safeIntegers` 开关   | 差异落在 `packages/db` 适配层内部，业务层不感知    |
| 生态核对        | 无 npm 依赖、无编译链；API 面较小              | 生态成熟、文档全、API 稳定                           | 面向本项目 600 条基线，两者都富余                |

**结论**：实测两者量级打平（插 5k 行都在 22\~25 ms，余项差异 <1.5 ms），**性能不构成决策依据**；判定维持总纲倾向，理由落在**工程形态**——**Bun + bun:sqlite 为 Track B / 本地开发默认**：① Bun 内置零依赖、无原生模块 ABI 匹配问题（better-sqlite3 每换 Node 大版本需重装/重编译）；② `packages/db` 适配器保留 `better-sqlite3` 为 Node 回退，Drizzle 方言差异收敛在适配层，业务层不感知；③ 若未来 CI/宿主环境不便跑 Bun，走 Node 轨兜底，无需改业务代码。
