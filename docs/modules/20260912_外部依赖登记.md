# 外部依赖登记

## 1. fflate（已引入，2026-09-12）

| 项 | 内容 |
| --- | --- |
| 用途 | 备份本地导出/导入的 ZIP 打包与解包（`GET /api/backup/export-zip`、`POST /api/backup/import`） |
| 许可 | MIT |
| 版本/位置 | `fflate@^0.8.3`，仅 `apps/server/src/backup/`（动态 import，两处） |
| 摘除步骤 | ① 删 `backup-routes.ts` 的 `/export-zip` 与 `/import` 路由；② 删 `backup-service.ts` 的 `exportZip()`；③ `pnpm --filter @dogear/server remove fflate`；④ API 结构表 v1.7 两行与 BackupTab 的「本地导出/导入」区块。无数据耦合、无其他引用 |

## 2. metascraper 系（已引入，2026-09-12，Track B 专用）

| 项 | 内容 |
| --- | --- |
| 用途 | 保存书签后的元数据提取增强（标题/摘要/封面/作者/日期/图标），替代内置正则提取的准确性短板 |
| 许可 | MIT |
| 版本/位置 | `metascraper@^5.56.2` + 规则包 `metascraper-{title,description,image,author,date,logo}`；仅 `apps/server/src/archive/metadata-enhancer.ts`，经 `index.ts` 注入（Workers **不引入**，bundle 不受影响） |
| 回退行为 | 增强提取失败自动回退内置轻量提取（`archive/metadata.ts`），功能不中断 |
| 摘除步骤 | ① 删 `metadata-enhancer.ts`；② 删 `index.ts` 的 `metadataEnhancer` 注入行；③ `pnpm --filter @dogear/server remove metascraper metascraper-title metascraper-description metascraper-image metascraper-author metascraper-date metascraper-logo`。回退后元数据质量下降但功能完整 |

## 3. monolith（系统二进制，2026-09-12，Track B 专用）

| 项 | 内容 |
| --- | --- |
| 用途 | 快照执行器：抓取公开页产出内联资源的单 HTML（L3「无 DOM」路径），产物落 `data/snapshots/<jobId>.html` 并写入 `archives.file_path` |
| 许可 | CC0（公共领域） |
| 形态 | **外部二进制**（非 npm）：Dockerfile 已 `apk add monolith`；裸机自装（`cargo install monolith` / 包管理器），可用 `DOGEAR_MONOLITH_BIN` 指向自定义路径 |
| 位置 | `apps/server/src/archive/snapshot-monolith.ts`（注入式，Workers 不引入） |
| 边界 | 登录墙页面抓不到（预期失败，那类页面走浏览器侧 SingleFile）；失败标 Job failed + archives failed，**不回滚书签** |
| 摘除步骤 | ① 删 `snapshot-monolith.ts`；② 删 `index.ts` 的 `snapshotProcessor` 注入；③ 删 `app.ts` 的 `/api/archive/process` 路由（或保留路由返回 501 的分支，该分支本就处理未注入情形）；④ 删 Dockerfile 的 `apk add monolith` 行。`archives` 表结构保留（含历史记录），无迁移 |

## 4. single-file-core（已批准、待引入——浏览器侧消费者属下一批）

| 项 | 内容 |
| --- | --- |
| 用途 | 浏览器侧快照：工作台领 `queued_pending_browser` 的 Job 后，在目标页面上下文压缩 DOM 为单 HTML 上传（L3「有 DOM」路径） |
| 许可 | **AGPL-3.0**——隔离约束：单独成包（拟 `packages/snapshot-core`），服务端只收 HTML blob，AGPL 代码不进 Hono/Drizzle 主栈 |
| 现状 | **尚未安装**。浏览器侧消费者需要真实浏览器环境（打开目标页 + 注入执行 + 上传回传）开发与联调，作为独立批次进行；本批先完成服务端 monolith 路径与登记 |
| 引入时登记 | 装包后在本表补版本/位置/摘除步骤（卸载包 + 删包目录 + 删工作台领任务入口即可，服务端 archives 语义不变） |

## 5. 登记规则

- 任何进入 package.json 的**新生产依赖**与任何**系统级外部二进制**，落地当天在本文件登记（用途/许可/位置/摘除步骤）。
- 摘除某依赖时，同步删掉本表条目或标注「已摘除 + 日期」。
