# M1 骨架执行计划

## 1. 目标与边界

### 1.1 目标

把仓库变成一条最小真实链路：服务端接收一条 Bookmark，写入服务端真源，工作台通过真实 API 读出；服务重启后数据仍然存在。

### 1.2 本程做

- 初始化 pnpm workspace 与 Turborepo。

- 初始化 `apps/web`、`apps/server`、`packages/shared`、`packages/db`。

- 用 Zod 定义 Bookmark 最小契约：`id`、`url`、`status`，其中 `id` 为 UUID，`status` 默认 `unread`。

- 用 Drizzle 定义最小 bookmarks 表和迁移。

- 接通本地 SQLite 真源，并保留 D1 适配器冒烟入口。

- 用 Hono 提供 Bookmark 创建和列表 API。

- 工作台用 React 19 + Vite 请求真实 API并展示列表。

- 提供根级开发与 typecheck 脚本。

- 完成停服、重启、再次查询的数据持久化验证。

### 1.3 明确不做

鉴权、Dexie/IndexedDB、Raindrop、S3、WebDAV、Snapshot、Metadata、AI、Skill API、搜索、Scene、Folder、Tag、回收站、访问记录、同步状态栏、插件、导航页和任何生产部署改造。

## 2. 技术约束

- 包管理与 workspace 采用技术总纲已定的 pnpm + Turborepo，不用 npm workspace 替代。

- Track B 本地开发默认使用 Bun + `bun:sqlite`；Node + `better-sqlite3` 仅保留技术总纲规定的回退路径。

- `packages/shared` 不依赖应用层；`packages/db` 只负责 Drizzle schema、迁移和 D1/SQLite 驱动适配。

- 不引入 Dexie；不建立第二真源。

- 服务端负责生成 UUID，创建响应返回正式 id；不使用 `tmp_` id。

- 工作台禁止使用 mock/fixture 作为主数据源。

- 本程不修改 `wiki/`，不修改根目录 `DESIGN.md`；M1 不需要新视觉规范。

## 4. M1 验收标准

### 必须通过

- 提交一条 URL 后，列表出现该条。

- 返回的 `id` 是 UUID，且刷新后保持不变。

- 工作台列表来自真实 API，不是写死数组。

- 停止并重启 server 后，数据仍可查询。

- 根 typecheck 通过。

### 必须确认未引入

- Dexie 或其他端侧缓存。

- 鉴权中间件。

- Raindrop、S3、WebDAV 客户端。

- Snapshot、Skill、AI、搜索或四维组织逻辑。

### 不纳入 M1 通过条件

- D1 的真实云端部署；M1 只要求 D1 适配器最小冒烟，无法运行时须记录原因。

- UI 与原型的高保真一致。

- 生产环境安全加固和部署自动化。
