# 状态栏任务进度 + 工作台列表分页 · 屏稿

## 1. 背景

两个用户诉求（2026-09-13）：

1. 导入 Raindrop 书签时希望随时看到进展（导到多少条），且**在最底部状态栏常驻显示**——此前进度只在设置页通道行内，切页即看不见。
2. 导入后（397 条量级）列表希望**分页管理**，而不是「加载更多」的追加式浏览。

## 2. 状态栏任务进度

- 数据源：全局 `channel-tasks.ts`（导入/导出分页循环所在），`StatusBar` 用 `useSyncExternalStore` 订阅，任何页面都实时可见。
- **只在任务运行中显示**；完成/失败由 toast 与设置页行内文案承载，状态栏不留陈旧状态。
- 文案：`导入中 37 / 397 条（第 1 页）`、`导出中 12 / 40 条`；总数未知时省略分母。mono 小字、琥珀色（`--amber`，DESIGN.md §2 强调色角色），与「待同步 N」并排、右对齐。
- 与撤销入口共存：撤销按钮仍走 `statusbar-spacer` 右对齐，任务进度在其左侧。

## 3. 工作台列表分页器（`/` Inbox 与 `/bookmarks` 共用）

### 3.1 结构

- 摘要行：`共 N 条`（N=服务端 total；旧「显示 x 条（还有更多）」废弃）。
- 列表底部（原「加载更多」位置）：`上一页 · 第 x / y 页 · 下一页`。
  - `y` 来自 `ceil(total / 50)`；total 缺省（理论不应发生）时只显示 `第 x 页`。
  - 第 1 页禁用「上一页」，末页（`nextCursor` 为空）禁用「下一页」；单页时不渲染整个分页器。
- 翻页替换当前内容（不追加），翻页期间骨架屏，快速连点用请求序号丢弃旧回执。

### 3.2 取数语义（为什么没有「跳到第 N 页」）

- 服务端列表是 **keyset 游标分页**（排序键写入游标，保证翻页不漏不重，见 repository.ts 注释）。游标只能按页链式发现，天然支持上一页/下一页，**不支持任意跳页**。
- 备选方案（未采纳）：列表改 offset 分页换取数字页码直跳。代价：数据变化时漏项/重项回归、与既有游标契约冲突。397 条 ≈ 8 页，翻页成本极低，暂不为跳页引入第二套分页语义；若书签量级上到数千、跳页成为刚需，再立批次改 offset。
- 筛选/排序/切换 Inbox↔书签：回到第 1 页（游标栈重置）。撤销/批量操作后：**刷新当前页**（与旧行为一致）。
- 已知取舍：跨页选择、⌘K 命令面板与工具栏「整理建议」计数的覆盖范围从「已加载累计」变为「当前页」；导航页（/nav）的「加载更多」本轮未动。

## 4. 空状态与异常

- 空态、筛选空态、加载失败与旧版一致；因删除导致当前页为空的边缘情况，分页器仍显示（`上一页` 可退），不误报「暂无书签」。
