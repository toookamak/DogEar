# 同步功能设计

## 1. 设计目标

Raindrop 作为可选第三方通道，提供 Token 认证的自动/手动同步能力。不是备份，而是**双向的通道同步**，涉及冲突处理、导入梳理等逻辑。

## 2. 配置项

| 配置项 | 说明 |
| --- | --- |
| Token | Raindrop API Token（测试令牌或 OAuth），输入框显示前3后3，中间用* |
| 自动同步 | 开关，开启后按设定的时间间隔自动同步 |
| 同步间隔 | 每15分钟 / 每30分钟 / 每小时 / 每6小时 / 每天 |
| 手动同步 | 按钮，点击立即执行一次同步 |
| 最近同步 | 显示最近一次同步时间和状态 |

## 3. 同步行为

- **同步方向**：双向（Raindrop → DogEar 真源；DogEar 真源 → Raindrop）
- **冲突处理**：本地优先（保留本地版本，Raindrop 版本作为副本保存）
- **导入新书签**：默认进入 Inbox，可跳过导入梳理页
- **不同步**：Scene、Status、回收站内容不写回 Raindrop
- **同步记录**：每次同步记录日志，显示最近同步时间和状态

### 3.1 队列消费（v0.2 落地，2026-09-12；v0.4 升级 payload 契约）

**入队（写路径）**：书签 create / 单条 update / 单条 delete / 批量（逐条）/ Skill 保存成功后，若存在**已启用且配置了 Token 的 Raindrop 通道**，向 `sync_queue` 入队一条 `('create'|'update'|'delete', 'bookmark', 书签id, 'raindrop', payload)`，并把该书签 `syncStatus` 标为 `pending`（消费成功后标回 `synced`）。

**payload 契约 v2（v0.4，2026-10-03，批次 0.5/0.6）**——远端语义实测后重写（见 §3.1.1）：

| 字段 | 何时携带 | 消费语义 |
| --- | --- | --- |
| `url` | 恒带（定位符） | create 必需；update 原值回传 |
| `raindropId` | 已推送过才有 | 定位符；update 无它时降级为 create |
| `title` / `note` | **仅被编辑时** | 部分更新：不带则远端保持原值 |
| `tags` | 标签集合被编辑时 | **全量集合，整体替换**；`[]` = 清空远端标签 |
| `folderId` | 收藏夹被编辑时 | 存**本地 id**；消费时反查 `folders.raindrop_id`（映射可能在排队期间才建立）；`null` = 移到 Unsorted（-1） |
| `addTags` + `srcCollection` | 批量加标签时，**成对出现** | 攒批形态：`srcCollection` 是该书签远端当前所在集合（入队时解析），消费按其分组走批量接口 |

- **只推真编辑字段**（§3.6.1 推送最小化）：status / scene / important 等本地维度的编辑**不入队**（推一次 no-op PUT 纯属浪费额度）。
- `srcCollection` 解析优先级：本地 folder 映射 → `raindropExtras.collectionId`（拉取时记录，覆盖 Unsorted 与「收藏夹被删」）→ 都拿不到则该条退回单条全量路径；`-99`（Trash）不可作作用域。

**只推 Raindrop 的决定**：队列只承载 Raindrop **书签级**推送。S3 / WebDAV 是**文件级**导出（整库 JSON），没有逐条变更语义，保持手动触发（既有 `POST /api/channels/:id/export`）；误入队的非 Raindrop 书签级条目会被消费器标 `failed`（禁止无 handler 假装成功）。

### 3.1.1 Raindrop 远端写入语义（v0.4，2026-10-03 实测定稿）

以下结论全部用真实 token 在独立测试收藏夹实测得出（测完即删），作为消费器实现依据；官方文档未写明的部分以实测为准：

| 操作 | 实测语义 | 消费器对策 |
| --- | --- | --- |
| 单条 PUT 不带 `tags` | 标签**保留** | 部分更新安全：没编辑标签就不带该字段 |
| 单条 PUT 带 `tags` | **整体替换** | `tags` 必须全量携带；部分携带会丢标签 |
| 单条 PUT `tags: []` | **清空** | 用户清空标签时可如实推送 |
| 单条 PUT `collection: {$id}` | 移动生效 | 正确形态是 `{$id}`；`{id}` 被静默忽略（书签留在原地） |
| 批量 PUT `tags` | **追加**（与已有并存） | 批量加标签安全；**批量删标签做不到**（追加无法减标签），删除走单条替换路径 |
| 批量 PUT `tags: []` | **清空** | 护栏：空数组绝不进批量请求体（客户端与消费器双重挡） |
| 批量 PUT `collection: {$id}` | 移动生效 | path 收藏夹 = 移动目标的分组键之一 |
| 批量 path `/{collectionId}` | **作用域过滤** | 只影响该集合内的 ids，不在其中的**静默跳过**——攒批必须按条目「远端当前所在集合」分组，宁可不攒不能错攒 |

**攒批规则（批次 0.8）**：只有「纯批量加标签」的更新项（payload 仅 `addTags` + `srcCollection` + `raindropId`）可入组，按 `(源集合, 标签集)` 分组，一次 `PUT /raindrops/{collectionId}` 推 ≤100 条。混入其他字段属于契约破坏，消费器失败暴露，不静默降级。

**已知窗口（如实记录）**：同一书签先「批量加标签」后「集合替换」、且两笔分属两次消费时，错序会丢一次编辑（追加与替换的先后无法仅凭队列顺序完全复原）。窗口由「编辑后尽快消费」压到最小；真实分歧由拉取侧 reconcile（只补空不覆盖）与差异探测兜底。

**映射失效（决策七）**：`folderId` 有值但 `folders.raindrop_id` 查不到时，该条**挂起**（标 failed，错误信息写明「未映射到远端集合」），映射建立后退避重试自动恢复——推不出去就不推，绝不悄悄推成别的样子。

| 调度 | 时机 | 说明 |
| --- | --- | --- |
| Workers Cron | 每 5 分钟（`wrangler.toml [triggers]`，轨 A） | `worker.ts` 的 `scheduled` |
| 自托管定时器 | 每 60 秒（轨 B） | `index.ts` setInterval，带防重入 |
| 工作台触发 | `POST /api/sync/process` | 客户端攒批 flush 时调用；**已升级**：消费一批（最多 10 条）并返回摘要 `{processed, succeeded, failed, requeued, remaining}`，不再是占位 |

消费逻辑：先把「退避到期」的 failed 项重置回 `pending`（`retry_count` 不清零），再逐条处理 pending：按 `action` 调 Raindrop create/update/delete；create 成功后把远端 `_id` 写回 `bookmarks.raindropId` 并标 `syncStatus='synced'`；delete 的书签若无 `raindropId`（从未推送过）视为成功。

**429 退避与重试上限**：任何失败（含 429 限流，RaindropClient 的错误带 `status`）标 `failed` 且 `retry_count` 加一；退避序列 **1s → 2s → 4s（封顶）**，按 `updated_at + backoff(retry_count)` 判断到期；超过 **8 次**不再自动重试（防毒条目），保留在队列可人工排查。



### 3.2 拉回侧（v0.3 落地，2026-09-12）

- **入口**：`POST /api/sync/pull`（工作台 Raindrop 通道行「拉取」按钮）；通道「导入」仍为显式全量（全页循环，用户主动触发）。
- **低频约束（防 Raindrop 风控）**：每次调用只拉 **1 页（50 条）**，不自动翻页；响应 `hasMore` 提示远端还有更多，是否继续由用户决定。自动调度**不**做拉回（只有推送有 Cron）。
- **新增**：按 `raindropId` 找不到的远端条目 → 创建，`source: 'raindrop'`，状态进 Inbox（默认；`intoInbox:false` 则 saved）。
- **冲突（本地赢）**：已有书签且远端较新（`lastUpdate` > 本地 `updatedAt`）且内容有差异（title/url/note 规范化比较）→ 本地**不动**，`conflicts` 表记两端快照；同 raindropId 只留一条 pending，解决后再次出现差异会生成新记录。
- **解决**：`kept_local`（仅标记）/ `kept_remote`（远端覆盖 title/note）/ `merged`（本地为基，远端非空字段补齐）；支持批量。UI 在设置 → 输入源/导出的「同步冲突」面板（有 pending 才出现）。
- **不做**：Scene/Status 不拉回映射（Raindrop 无对应概念）；回收站内容不参与拉回。

## 5. 边界与不做

| 不做 | 原因 |
| --- | --- |
| 不写回 Scene/Status 到 Raindrop | 仅 Link 级别同步，Raindrop 无 Scene/Status 对应概念 |
| 不自动发现 Raindrop 账号 | 需用户手动填入 Token |
| 不作为唯一真源 | DogEar 真源（SQLite/D1）始终为权威数据源 |
| 不替代全局备份 | 备份归入备份功能设计，Raindrop 是单向通道非备份 |
| 配置节流的「自动同步间隔」暂未接调度 | 当前调度固定（Cron 5 分钟 / 自托管 60 秒）；间隔选项待设置页接入消费器参数后生效 |
