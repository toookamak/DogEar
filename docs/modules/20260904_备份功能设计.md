# 备份功能设计

## 1. 设计目标

让用户能**自己决定**把书签数据备份到哪里、多久备份一次、备份什么内容。不是按统一频率跑所有备份，而是**每个备份目标独立设置频率**。

Raindrop 作为第三方通道单独配置，不并入备份目标体系。

## 2. 备份模型

### 2.1 核心概念：备份目标（Backup Target）

一个备份目标 = 一个存储位置 + 它的专属设置。用户可配置多个备份目标同时运行。

| 维度 | 设计 |
| --- | --- |
| 类型 | S3 兼容存储 / WebDAV |
| 频率 | **每个目标独立设置**：数字 + 单位（小时/天）。设为 0 表示不自动备份 |
| 内容 | 每个目标独立勾选：□ 书签表（CSV） □ 快照（如有）。两项独立，互不绑定 |
| 保留上限 | 每个目标独立设置最多保留几份备份，超出则滚动删除最旧的 |
| 历史记录 | 每份备份运行记录可单独查看详情、恢复、删除远程文件 |
| 最近备份 | 每个目标独立记录最近一次备份时间、状态、文件数、字节数 |
| 开关 | 每个目标可单独启用/禁用 |

### 2.2 全局自动备份开关

- 一个**总开关**，关闭后所有目标的自动备份均停止
- 手动触发"立即备份"不受总开关影响，单个目标启用/禁用也不受总开关影响
- 这个开关解决的是"临时不想让后台跑备份"的场景，不需要逐个去关

### 2.3 内容选择

每个目标独立勾选备份内容，两个复选框独立，互不绑定：

| 选项 | 说明 |
| --- | --- |
| □ **书签表（CSV）** | 导出书签结构化数据为 CSV 格式，包含所有字段 |
| □ **快照** | 附加快照文件（HTML 网页归档）。只有有快照的书签才附带文件 |

至少勾选一项才能执行备份。仅勾选快照时，备份包含快照文件 + 对应的书签 CSV（自动包含）。

### 2.4 备份目标字段模型

```
BackupTarget {
  id: string (UUID)
  type: 's3' | 'webdav'
  name: string (用户可自定义名称)
  enabled: boolean (单独启用/禁用)
  scheduleInterval: number (备份间隔数值，0 表示不自动备份)
  scheduleUnit: 'hours' | 'days' (间隔单位)
  includeBookmarks: boolean (是否包含书签 CSV)
  includeSnapshots: boolean (是否包含快照文件)
  retentionLimit: number (保留上限，0 表示不限。超过上限时，执行新备份前先删除最旧的超出部分)
  config: S3Config | WebdavConfig (连接信息，按类型不同)
  secret: string | null (加密存储的凭证)
  lastRunAt: number | null (毫秒时间戳)
  lastStatus: 'success' | 'failed' | null
  lastError: string | null (失败时的错误信息)
  lastFileCount: number | null (上次备份的文件数)
  lastByteCount: number | null (上次备份的字节数)
  createdAt: number
  updatedAt: number
}
```

#### S3 配置

```
S3Config {
  endpoint: string (端点 URL，支持 MinIO 等兼容 S3)
  region: string
  bucket: string
  prefix: string (可选路径前缀，如 "dogear/backup/")
  accessKeyId: string
  secretAccessKey: string (加密存储)
}
```

#### WebDAV 配置

```
WebdavConfig {
  url: string (WebDAV 端点 URL)
  username: string
  password: string (加密存储)
  path: string (远程路径，如 "/dogear/backup/")
}
```

### 2.5 备份执行逻辑

1. 调度器定时扫描所有启用的备份目标，检查其 `scheduleInterval`/`scheduleUnit` 是否到期
2. 全局自动备份开关关闭时，跳过所有目标的自动调度
3. 按目标的内容选择（`includeBookmarks`/`includeSnapshots`），导出对应数据，创建 `BackupRun` 记录（含远程文件路径、状态、文件数、字节数）
4. 每个目标独立记录最近一次运行信息到 `BackupTarget`
5. 失败时记录错误信息，下次调度重试
6. 手动"立即备份"不受全局开关和单个目标启用/禁用限制
7. **滚动保留**：若 `retentionLimit > 0`，执行新备份前查询该目标已有的成功备份记录数，超过上限时按时间倒序删除最旧的超出部分（包括远程文件 + 本地记录），再执行新备份
8. **单份删除**：用户可在备份历史列表中对某份备份点击删除，删除远程文件 + 该条运行记录，不触发滚动保留逻辑

### 2.6 连接测试

- 编辑或创建备份目标时，提供 **[测试连接]** 按钮
- 用当前输入的配置（URL、凭证、路径等）尝试连接远程目标
- 测试结果：成功 ✅ / 失败 ❌（显示具体错误信息如"连接超时"、"认证失败"等）
- 测试不保存目标，仅验证连通性
- 连接测试成功后才允许保存目标

### 2.7 备份产物

| 内容组合 | 产出 |
| --- | --- |
| 仅书签 CSV | `dogear_bookmarks_YYYYMMDD_HHmmss.csv` |
| 仅快照 | `snapshots/` 目录下所有关联的快照 HTML 文件 + `dogear_bookmarks_YYYYMMDD_HHmmss.csv`（自动含书签表） |
| 书签 CSV + 快照 | 上述两者合并 |

CSV 格式：UTF-8 with BOM，包含所有 Bookmark 字段（URL、标题、摘要、备注、Scene、Folder、Tag、状态、标星、创建时间、更新时间等）。

### 2.8 备份运行记录（BackupRun）

每次备份执行（无论自动还是手动）都会创建一条运行记录，用于追踪历史和删除远程文件。

```
BackupRun {
  id: string (UUID)
  targetId: string (关联 BackupTarget.id)
  status: 'running' | 'success' | 'failed'
  startedAt: number (毫秒时间戳)
  completedAt: number | null
  files: BackupRunFile[] (本次备份产出的文件列表)
  fileCount: number
  byteCount: number
  bookmarkCount: number (本次备份包含的书签链接数)
  snapshotCount: number (本次备份包含的快照文件数)
  error: string | null (失败时的错误信息)
}

BackupRunFile {
  path: string (远程文件路径，如 "dogear/backup/20260904_103000.csv")
  size: number (字节)
  type: 'csv' | 'snapshot_html' (文件类型)
}
```

#### 展开查看详情

- 备份历史列表中的每条记录默认显示摘要行
- 点击记录行或 **[展开]** 按钮，展开显示详情面板：
  - 包含的书签链接数：`bookmarkCount` 条
  - 包含的快照文件数：`snapshotCount` 个
  - 文件清单：列出所有 `BackupRunFile`，每个文件显示路径、大小、类型
  - 备份时间范围：`startedAt` → `completedAt`

#### 恢复操作

- 每份备份记录旁有一个 **[恢复]** 按钮
- 点击后弹出**二次确认对话框**：
  ```
  确认恢复此备份？
  将用备份数据覆盖当前书签库。
  覆盖范围：□ 书签表（CSV） □ 快照
  [取消] [确认恢复]
  ```
- 恢复逻辑：
  - CSV 恢复：用备份中的书签 CSV 数据**覆盖**当前真源中的书签表（全量替换，非增量合并）
  - 快照恢复：用备份中的快照文件覆盖当前快照目录
  - 覆盖范围可勾选，默认全选
  - 恢复前自动创建一次全量备份作为"回滚点"
  - 恢复完成后记录操作日志
- 恢复不触发滚动保留逻辑

#### 删除操作

- 每份备份记录旁有一个 **[删除]** 按钮
- 点击后弹出**二次确认对话框**：
  ```
  确认删除此备份？
  将删除远程目标中的对应文件，此操作不可撤销。
  [取消] [确认删除]
  ```
- 确认后执行：删除远程目标中对应的文件 → 删除本地 `BackupRun` 记录
- 删除后目标 `lastRunAt`/`lastStatus` 更新为最近一条成功记录（若无则置空）
- 删除操作不触发滚动保留逻辑（滚动保留 = 自动，删除 = 手动）

#### 历史列表字段

| 字段 | 说明 |
| --- | --- |
| 备份时间 | `startedAt` 格式化为本地时间 |
| 状态 | 成功 / 失败（失败时显示错误信息） |
| 摘要 | 文件数 + 链接数 + 快照数（如"3文件 · 120链接 · 2快照"） |
| 大小 | 字节数格式化为人类可读（KB/MB） |
| 内容 | CSV / 快照 / CSV+快照 |
| 操作 | [展开] [恢复] [删除] |

## 3. 本地导出与导入

独立于备份目标，在设置页面提供本地导出/导入功能，用于手动将书签数据导出到本地文件，或从本地文件恢复书签数据。

### 3.1 导出

#### 导出内容

两个独立复选框，可自由组合：

| 选项 | 说明 |
| --- | --- |
| □ **书签表（CSV）** | 导出书签结构化数据为 CSV 格式，包含所有字段 |
| □ **快照** | 附加快照文件（HTML 网页归档）。只有有快照的书签才附带文件 |

至少勾选一项才能执行导出。

#### 导出产物

- 打包为 **ZIP 压缩包**，文件名格式：`dogear_export_YYYYMMDD_HHmmss.zip`
- ZIP 内目录结构：
  ```
  dogear_export_YYYYMMDD_HHmmss/
  ├── bookmarks.csv          (勾选书签表时)
  └── snapshots/             (勾选快照时)
      ├── <uuid1>.html
      └── <uuid2>.html
  ```
- 导出不写入真源，不影响备份运行记录
- 导出通过浏览器下载触发，文件保存在用户本地

### 3.2 导入

#### 导入方式

- 支持两种文件格式：
  - **CSV 文件**：单独导入书签表 CSV，覆盖当前书签数据
  - **ZIP 压缩包**：导入导出时生成的 ZIP 包，可同时恢复书签表和快照

#### 导入操作

- 点击 **[导入]** 按钮，弹出文件选择对话框
- 选择文件后，系统自动识别文件类型（CSV / ZIP）
- 弹出**二次确认对话框**：
  ```
  确认导入？
  当前数据将被覆盖，导入前系统会自动创建一次全量备份。
  检测到文件类型：CSV / ZIP
  包含内容：□ 书签表（CSV） □ 快照（仅ZIP）
  [取消] [确认导入]
  ```
- 确认后执行：
  1. 自动创建一次全量备份作为"回滚点"
  2. 覆盖当前真源中的书签表（CSV 数据）/ 快照目录（ZIP 中的快照文件）
  3. 导入完成后记录操作日志
  4. 导入不触发备份目标的滚动保留逻辑

## 5. 边界与不做

| 不做 | 原因 |
| --- | --- |
| 备份 SHA-256 校验 | 按用户已有规则仅在更新前验证，备份本身不做校验 |
| 多用户备份 | 当前为单用户，备份目标直接关联用户 |
| 备份到本地文件系统 | 仅 S3 和 WebDAV 两种远程目标（本地导出为独立功能，非备份目标） |
| 增量/差异备份 | 全量备份，按频率执行，保留上限控制空间 |
| 加密备份内容 | 传输加密由 S3/WebDAV 通道保障，不自做内容加密 |
| 备份文件的自动过期清理 | 不按时间自动删除，仅通过保留上限滚动删除 + 手动删除 |
| Raindrop 同步 | 归入同步功能设计，不在此文档中 |

## 6. 与 M6 开发计划的关系

本文设计的备份目标模型覆盖 M6 开发计划中的"三档备份"需求：

- **轻档（CSV 书签表）** → 勾选 `includeBookmarks`，不勾 `includeSnapshots`
- **重档（书签 + 快照）** → 同时勾选 `includeBookmarks` 和 `includeSnapshots`
- 中档（+配置）暂不纳入第一期，可在后续版本扩展新增复选框

M6 实现时，按本文模型开发备份目标 CRUD + 调度引擎 + S3/WebDAV 交付器 + 连接测试 + 本地导出/导入 + 设置页面 UI。
