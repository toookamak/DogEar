## 1. Scene（已确认方向的细部）

### 1.1 PRD 已定（此处不改结论）

摘自 PRD §2.0.1–§2.0.4，防止只改 PRD 后本文失锚：

- Scene 表示「我为什么保存 / 准备在什么情境下使用」，可扩展、可配置，**不是**硬编码枚举。
- 默认预设四场景：工作研究 / 灵感收集 / 稍后再读 / 长期资料；用户可新建、改名、合并、停用、删除。
- Bookmark ↔ Scene **多对多**；Capture **不强制**选 Scene；Inbox **不强制**转出。
- AERR（Action / Explore / Read / Reference）是系统内部原型，**不展示给用户**；默认四场景各挂一个。
- **一套工作台**，按当前 Scene 所挂原型调整默认排序 / 密度 / 主操作。
- 第一版 **不做 Primary Scene**；呈现上下文 = 用户当前所在的 Scene 视图。
- 「稍后再读」是 Scene，不是 Status。禁止用 Tag 表达「以后可能用 / 工作要用」。

### 1.2 Scene 配置对象（从 PRD v1.0.5 §2.0.1 迁入）

```text
Scene
├── id
├── name
├── description
├── icon / appearance（可选）
├── sort_order
├── enabled / archived
├── aerr_archetype（系统内部：action / explore / read / reference；v1.0.5 原文未列字段名，v1.0.6 补方向）
├── created_at
└── updated_at
```

- 用户新建 Scene 时系统给一个默认原型（可改）；用户不必理解 AERR 四个词。
- 「纯备份」并入 Reference，不单列第五种原型。
- **待设计**：`aerr_archetype` 的存储名、是否允许一个 Scene 改挂原型、改挂后已有书签的呈现是否立即跟着变。

### 1.3 AERR 与默认 Scene（从 PRD v1.0.5 §2.0.3 迁入）

| 原型 | 含义 | 默认挂到 |
| --- | --- | --- |
| Action | 近期要拿它办事 | 工作研究 |
| Explore | 浏览、发散、找灵感 | 灵感收集 |
| Read | 准备消费掉 | 稍后再读 |
| Reference | 以后反复查 | 长期资料 |

同一书签出现在不同 Scene 时，跟随**当前视图**的原型呈现。第一版可先共用列表，只换主操作文案。

**待设计**：各原型对应的默认排序、密度、主按钮文案清单（PRD 只定「会变」，未定具体值）。

### 1.4 成员表（待设计）

**存储口径（2026-09-04）**：已确认的场景归属、未确认的建议，分别落 `bookmark_scenes` 与 `suggestions`，见 [数据库设计](./数据库设计.md) §6.3 / §6.6；工作台确认与 Skill 建议窗口见 [API 设计](./API设计.md)。本文以下仍管交互与未决细部，不另定一套表。

PRD 明确不在正文展开。开放问题（从 v1.0.5 说明栏迁入）：

- 关联表建议方向：`bookmark_id` + `scene_id` + `source`（user / ai_suggest / ai_accepted）+ `confidence`（可选）+ `created_at`
- 一条书签 0..N 条成员记录；删除 Scene 时成员如何处理（随停用隐藏 / 提示迁移 / 禁止删除仍有成员的 Scene）
- AI 建议未采纳时：是否写成员表，还是只写「建议」表
- **不做 Primary 字段**（已决）；若将来做，不回写进核心需求

### 1.5 合并 / 停用 / 删除（待设计）

PRD 允许 Scene 合并、停用、删除，未定工作流：

- 合并：成员并入目标 Scene；是否保留「曾属于」历史
- 停用：入口隐藏，已有成员是否仍可按旧 Scene 筛到
- 删除：有成员时的拦截与迁移向导
- 默认四场景是否允许全部删光（方向倾向：允许，但空列表时工作台仍可用 Inbox / Folder / Tag）

### 1.6 Scene 与 Raindrop（PRD v1.0.7 已决）

**Scene 不进入 Raindrop。** 导出只作 Link 级存档，不表达 DogEar 使用场景。跨设备的 Scene 只走应用自身数据，不靠 Raindrop 标签编码。原先「`_scene:` 约定标签」候选作废，避免污染用户 Tag。

## 2. AI（已确认方向的细部）

### 2.1 核心 / 近期（从 PRD §2.0.4 / §4.2.7 / §4.4.3 迁入）

| 分层 | 做什么 | 不做什么 |
| --- | --- | --- |
| 核心需求 | 保存后异步理解；建议 1 个 Scene 和很少的 Tag/Folder；用户有一句话意图时按意图分流；建议默认可撤销 | 低把握乱贴场景；不经确认改结构；删除数据 |
| 近期需求 | 组织习惯记忆；闲置工作研究可建议迁到长期资料；相似 Scene 过多可提示合并 | 自动迁移、自动合并、自动生成一套分类哲学 |

两条记忆分开：书签记忆（核心，浅做）/ 组织记忆（近期）。

**建议出现位置（核心，v1.0.7）**：输入时（页面 / 插件 / Skill）、整理时、Inbox 界面内、未整理书签详情页。

`save_bookmark`：只建 Link；可选 `note` / `intent`；**不在此选择保存档位**；不默认自动写 Scene/Folder/Tag。保全走 `trigger_archive`。

v1.0.5 原文曾写 `archive_type` 可选、以及「AI 分类、生成标签」——已从 PRD Skill 表删除，以免与渐进式归档 / 建议先行冲突。若 Skill 合约落地文档仍保留 `archive_type`，视为过期。

### 2.2 置信度与建议落地（A1 已决，余项待设计）

开放问题：

- **「高把握才写 / 低把握不写」已不再成立（A1 口径已决）**：本版一律**建议先行**——系统可在后台**预备**建议（高把握时以更高优先级 / 更显眼的提示呈现），但**不自动挂 Scene**，写入须用户点击确认（PRD §2.0.2、总纲 §6.3「取舍说明」）。置信度阈值不再用于「决定自动写」；是否未来开放自动分流属远期评估（PRD §09 #21）
- 建议状态机：待处理 → 接受 / 稍后处理 / 忽略（PRD §4.2.7 已有产品态，缺字段）
- 批量采纳与批量撤销的粒度
- 隐私内容标记不进记忆（近期需求，PRD §6.3 已有方向）

### 2.3 迁移建议（近期需求，待设计）

- 「长期未访问」的时间阈值
- 只建议、不自动改（已决）
- 与访问记录（§4）的依赖：没有访问记录就无法做「闲置迁移」

## 4. 访问记录（核心需求要做，交互后定）

PRD §4.5：打开原链接（及日后打开 Snapshot）应留下访问记录。

**待设计**（本版只定「要记」）：

- 字段方向：`last_opened_at`、`open_count`，是否区分「工作台打开 / 导航页打开 / 插件打开」
- 是否记失败打开、预览面板打开（倾向：只记用户明确打开原链接或 Snapshot）
- 隐私：私密书签的访问记录是否进入 Rediscover 卡片
- 同步：仅存应用内，不入 Raindrop（倾向）
- UI：核心需求可以只落库、工作台暂不单独做「历史页」

## 5. 导航页圈选规则（PRD §4.3 / §09 #18）

### 5.1 已定

工作台控是否显示，导航页控布局。圈选方式：

- **全部**
- **按规则（或）**
- **自定义搜索勾选**
- **隐藏**（规则排除）

不是逐条点选作为唯一方式。关闭导航页 **不丢** `page_tab` / `docker_items`（与 `AGENTS.md` 一致）。

私密文件夹/标签默认不出现，除非规则明确纳入且需解锁。

### 5.2 待设计

- 规则算子：Folder / Tag / Scene / Status / 收藏标星 / 时间窗 的组合；「或」已定，是否要「且」
- 「全部」与「隐藏某文件夹」同时存在时的优先级
- 自定义搜索勾选：是否把搜索结果冻结成快照，还是每次打开导航页重算
- 预览：圈选后在工作台看到将出现在导航页的数量
- 匿名可见范围（§09 #12）仍未决：匿名 URL、搜索引擎收录、自定义域名

### 5.3 导航页布局（PRD §4.3.3 / §09 #1，从 v1.0.5 迁入）

已确认基础要素（PRD 正文仍保留）：图标+名称、文件夹聚合浮层、顶部搜索、固定区域规划、网格、Docker、Rediscover 卡片可放小组件区、私密需解锁。

仍待专题、不在 PRD 展开：

- 具体行列数与响应式规则
- 小组件的具体类型与尺寸
- 拖拽排序的完整交互
- 页面标签的详细设计（横/竖排布在归档反馈 v0.2.0 曾确认「都做、可切换」——**历史已确认，但 v1.0.6 仍把整页详细设计标待定**；落地时先核对此条，避免丢失）
- 跨页/跨区拖拽

固定区域顺序（方向，PRD 仍写「顺序待定」）：时间/搜索 → 页面标签 → 小组件 → 文件夹 → 书签 → Docker。

## 6. 删除与导出（PRD §4.2.12 / §09 #16）

### 6.1 已定（v1.0.7）

- 删除 = 应用内软删除（回收站）
- 导出 Raindrop 存档**默认不含回收站条目**
- 不再做删除标签双向推送
- 与 Status「搁置」、与内容 Archive 都不是同一件事

### 6.2 待设计

- 清空回收站是否影响已导出的 Raindrop 存档（默认不影响）
- 过期自动清空（默认 7 天）只处理应用内
- 回收站条目在工作台默认不出现在 Inbox / 各 Scene

已定：能连上本应用即可存；Raindrop / 对象存储等中断则写入应用内队列。

## 8. 内容提取链（从 PRD v1.0.5 §2.4 原文迁入，防丢失）

v1.0.6 正文改为：当前提取服务于 Metadata / 理解 / Snapshot；Reader 与手动选正文为远景。下面整棵降级树从 v1.0.5 保留，供远景中的 Reader 使用，**不是当前产品入口**。

```
URL / DOM
    │
    ▼
Primary Content Parser（通用解析）
    │
    ├── 成功 → Clean HTML
    │
    └── 失败
          │
          ▼
    Site-specific Rules（特定网站规则）
          │
          ├── 成功 → Clean HTML
          │
          └── 失败
                │
                ▼
          Browser Manual Select（用户手动选择正文区域）
                │
                ├── 成功 → 基于选中区域生成 Reader
                │
                └── 仍失败 → 保留 Original URL，Bookmark 不受影响
```

若用户明确要求完整保存：触发 Snapshot 流程（v1.0.6：发生在保存成功之后）。

## 11. 无本版产品入口的同步字段

这些字段在[技术总纲 §5.7 字段与 Raindrop 映射总表](../../wiki/DogEar-技术总纲.md) **保留映射**，避免与 Raindrop 对账时丢数据。不是「要做提醒功能 / 附件功能」。

| 字段 | 来源 | 本版产品入口 | 处理 |
| --- | --- | --- | --- |
| `reminder` | Raindrop 可给书签设提醒日期 | 无到期列表、无通知、无日历 | 读入只读保存 |
| `file` | Raindrop 附件 | 无上传/下载附件工作流 | 同步保留 |
| `creatorRef` | Raindrop 多用户引用 | 个人工具无含义 | 只读 |
| `highlights` | Raindrop 高亮 | 无高亮入口（v1.0.4 已决） | 读入只读 |
| 「优先级」/`_priority:` | 旧落地文档 / 旧排序文案 | 不单列属性；「我更在意」用收藏标星 | 落地文档若仍有约定，视为过期 |
