设计说明与改动对照

按 AGENTS.md「界面怎么做 / 先稿后码」：本稿只说清每一屏有哪些块、主操作、空状态，并逐条对照现状。确认前不写界面代码、不改全局样式、不改 DESIGN.md。

为什么动的是信息架构，不是配色

你的反馈都不是视觉问题。配色沿用现有 Notion 风不变，本稿只动三件事：①「哪里乱」从默认落点降为筛选条件，主入口保持全预览；②整理成为可进入可退出的独立模式，不改变你在哪；③「推没推」变成常驻可查状态，而不是设置页里的一个下拉。

⛔ 前置：Raindrop 收藏夹与标签目前是断的

读代码核实：拉取时 rd.tags 整个被丢弃、collection.$id 没映射到 bookmarks.folder_id；getCollections() / getTags() 定义了但全仓零调用；推送 payload 只有 url/title/note，collection 与 tags 从未送出；导出侧 tags: [] 硬编码。详见计划 §0.5。

对本稿的影响：屏 1/2/3 里的收藏夹与标签目前是本地数据，尚未与 Raindrop 打通。本稿的界面语义按「打通之后」设计，但批次 0 修好之前，屏 2 的批量操作无法验收。

维度现状本稿为什么
默认落点Inbox（待处理，Status 的一个值）全部收藏（全预览）你纠正过：主入口不能换成「哪里乱」，全标签浏览是主用途，DogEar 的第一身份是书签查询工具
侧栏Inbox / 书签 / 场景全部收藏 · 已收藏 + 收藏夹白卡 + 标签白卡 + 本地场景维持浏览强度，场景降级为本地维度
「哪里乱」类条件v0.1 稿做成侧栏一级项（未打标签 812 / 没归类的 1,240 …）收进筛选器，作为无状态条件「812 条没打标签」读起来像 812 件欠账；做成筛选条件，只是「我想看看没打标签的有哪些」
整理v0.1 稿把「哪里乱」当默认落点，整理是隐含的工具栏「整理」独立入口，进入后显示批量条，退出即回全预览整理是叠加在浏览之上的模式，不是一个你被丢进去的页面
Raindrop 连接设置 → 输入源/导出 → 添加通道 → 手填 Token留在设置页（屏 4），不是必选门槛你纠正过：不要放必选项。保留的只是把「连了会发生什么」讲清楚
组织维度场景 / 文件夹 / 标签 / 状态 四维平级收藏夹 + 标签 为主；场景降为「本地场景（不回写）」；状态隐藏四维里两维是 Raindrop 已有的，一维砍，一维降
主视图看板 / 网格 / 表格 / 标签 四视图平级列表为默认，网格为可选批量整理要密度和多选，看板对这个任务反而更差
批量操作顶部工具栏一行，选项多、易漏整理模式下选中即浮出独立操作条「一批 200 条 10 秒改完」是本产品相对 Raindrop 本体唯一不可替代的价值
同步语义顶栏胶囊「待同步 N」，入口在设置页「12 条待回写」+ 工具栏「同步一次」从「同步」改成「回写」，直接回答「我改的到了没有」
搜索⌘K 只索引已加载的那一页3,412 条全量端侧索引 + 行内直接改你原话「需要他完整好查」；现状确实搜不全
AI 建议 / Snapshot各占一处处入口隐藏（开关保留）AI 目前是空占位，留着只增加「看起来很复杂」
S3 / WebDAV设置页三个 tab 平级保留，位置降权按你的要求不删，后续会恢复

逐屏：块 / 主操作 / 空状态

屏 1 · 全预览（默认落点）

块：顶栏（视图名 + 总数 · 常驻搜索 · 回写胶囊） · 侧栏（全部收藏 · 已收藏 + 收藏夹白卡 + 标签白卡 + 本地场景 + 账户菜单） · 工具栏（整理 · 列表/网格 · 筛选 · 排序 · 同步一次） · 筛选弹层（无状态条件） · 列表（选择框 · 标题/来源 · 收藏夹 · 标签 · 收藏 · 日期） · 状态栏。

主操作：整理（工具栏最左 ghost）。这一屏没有实底主按钮——浏览不需要「主动作」，需要时才点整理。

关键设计：列表里有归类和没归类混在一起，缺的格子只留一个细点，不写「未归类／无标签」这种带评判的字眼；对应的筛选条件收在弹层里，弹层顶部明写「条件只是用来缩小范围的，可多选、可随时清空——不是待办清单，不会催你」。

空状态：筛选无结果 → 虚线框 + 「这些条件下没有收藏」+ 「清空筛选看全部 3,412 条」（主出口是回到全览，不是留在空结果里）。

屏 2 · 批量整理（整理模式）

块：与屏 2 同构，追加底部居中浮起的批量操作条（已选 N 条 · 移入收藏夹 · 加标签 · 加到本地场景 · 应用到 N 条 · 取消）。选中行 = 左 2px 橙条 + 内描边橙环（沿用 DESIGN.md §4 状态四件套，不新造样式）。

主操作：应用到 N 条（条内唯一实底橙）。

空状态：批量条不出现即表示无选中——不用额外的空态占位。跨页选择时状态栏持续显示「本页 4 / 已选 214」。

为什么这一屏写「未归类／无标签」而屏 1 只留细点？因为语境不同。屏 1 是全览，没筛，「细点」只是「这里是空的」的事实陈述；这一屏用户已经主动筛了「未打标签」，接下来就是批量填收藏夹和标签，需要一眼看清每条当前缺什么。这是响应用户意图的操作状态，不是我在替你评判欠账。

要你拍板的细节：「加标签」是追加还是替换？替换风险高（可能抹掉别人的归类），我倾向默认追加 + 单独提供「整理标签」入口。

屏 3 · 全量搜索

块：大搜索框（带高亮） · 命中统计条（条数 + 耗时 + 覆盖字段） · 结果列表 · 侧栏（搜索范围 + 收窄条件） · 状态栏（索引条数）。

主操作：结果行内直接改收藏夹／加标签（hover 显形）。这是本屏唯一新增能力，也是「搜到就能理」的落点。

空状态：无命中 → 「没找到 houdini」+ 三条建议（换个词 / 只搜标题 / 看看近半年新增）+ 「按标签 #Houdini 浏览」这个出口——搜索失败时给下一步，别只说没有。

屏 4 · 设置 · Raindrop 通道

块：设置左侧分区导航 · Raindrop 卡片（状态徽标 · 说明文案 · OAuth 主按钮 · 手填 Token 次入口 · 「连上之后会发生什么」三条） · 其他通道卡片（S3 / WebDAV，标注「保留可用」）。

主操作：用 Raindrop 账号连接（卡片内全宽、38px、橙底）。

关键设计：不做首次引导。打开工作台不会被打断去授权；连接入口安静地待在设置里。保留的是把后果讲清楚——连了会发生什么、什么会被回写、失败了怎么办。

空状态 / 未连接时：工作台顶栏胶囊显示「未连接」，不弹任何引导。点「同步一次」→ toast 提示「未连接 Raindrop，可在设置中连接」并给一个跳转设置的链接，不把人踢出当前上下文。

刻意没做的（以及原因）

  • 没做深色：本期只出浅色；深色结构同形，确认后另出一版，不在这稿里猜。
  • 没画详情面板：字段要按「Folder / Tag / Scene / 标题 / 备注」收敛，涉及取舍，等主稿定了一起出。
  • 没画完整的设置页六分区：只画了 Raindrop 通道这一张卡，说明它该长什么样；其余分区本轮不动。
  • 没动导航页：它在新定位里是「找」的旧解法，等搜索定稿后再决定去留。
  • 没动 DESIGN.md：本稿全部照它实现，没发现需要改视觉源的地方。若确认后有偏离，会单独提请你拍板。

需要你回的三件事

  • 先修 §0.5 断链还是先做界面？我建议先修——断链不修，屏 2 的批量操作无法验收（收藏夹和标签推不回 Raindrop）。
  • 「加标签」默认追加还是替换？替换可能抹掉已有归类，我倾向默认追加 + 单给「整理标签」入口。
  • 整理做成「模式」对不对？进整理时侧栏/搜索都还在，退出即回原位；另一种做法是整理做成独立页面（更彻底，但会丢失你当前的浏览位置）。
