# DogEar · 项目结构设计（预规划 v0.1）

> 基于《技术方案路线 v0.2》+《DATA_MODEL v1.1》+《COMPONENTS v1.1》，方向性，不建代码。后续开发禁止乱放文件，联动数据与组件。

## 1. 总览
```
DogEar/
├── docs/                          # 设计文档（PRD/模型/合约/拆解，本文件）
├── apps/
│   ├── web/                       # 工作台（Vite+React）  → 关联 M1/M4/M6
│   ├── extension/                 # 导航页插件（MV3）     → 关联 M4
│   └── server/                    # 本地服务（Hono+同步） → 关联 M1/M2/M3/M5
└── packages/
    ├── shared/                    # 共享类型/常量           → 关联 DATA_MODEL
    └── db/                        # 存储抽象（Dexie/SQLite）→ 关联 DATA_MODEL
```

## 3. 放置规则（强制）
- 新功能按上表归属，禁止根目录散落
- 跨模块共享放 `packages/shared`，组件先查 `COMPONENTS.md` 注册表
- 数据字段以 `DATA_MODEL.md` 为准，组件以 `COMPONENTS.md` 层级为准

## 4. 与落地拆解映射
- M1 存储抽象 → `packages/db` + `packages/shared/types`
- M2 同步引擎 → `apps/server/services/sync-service` + `apps/web/lib/sync-engine`
- M3 AI → `apps/server/routes/capabilities|bookmarks`
- M4 关联 → `apps/web/features/settings` + `apps/extension/newtab`
- M5 兜底 → `packages/db` 日志/备份
- M6 核心闭环 → `apps/web/features/inbox|bookmark`

> 后续建代码按此结构脚手架，变更需同步更新本文件与 docs/README.md。
